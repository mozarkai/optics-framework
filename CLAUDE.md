Guidance for coding agents (Claude Code, Codex, ...) in this repository. `AGENTS.md` is a symlink to this file, so edit only this one.

## Execute journey (CLI → driver action)

The chain behind `optics execute <folder>`:

1. `optics_framework/helper/cli.py:578` — `main()` dispatches via `ExecuteCommand.execute` (`cli.py:518`) → `execute_main(folder_path, runner, use_printer, include, exclude)` in `optics_framework/helper/execute.py:894`. `cli.py`'s helper imports sit in a `try/except ImportError` (`cli.py:20`) that shows the failure through `abort_with_panel` / `reinstall_guidance` (`helper/abort.py`); the package root resolves the `Optics` re-export lazily (PEP 562) so importing `helper.cli` doesn't load the vision stack before that guard runs.
2. `execute_main` delegates to `run_project` (`execute.py:1041`), which builds `ExecuteRunner(args)` (`execute.py:999`, subclass of `BaseRunner` at `execute.py:729`) and calls `asyncio.run(...)`. In-process callers (`quickstart`) use `run_project` to get a pass/fail value instead of `execute_main`'s `sys.exit(1)`.
3. `BaseRunner.__init__` (`execute.py:738`) discovers and loads synchronously:

A YAML with both `driver_sources` and `element[s]_sources`, or with a `devices` block (`is_devices_block`, `common/config_handler.py:102`), is the project config (`_is_config_file`, `execute.py:201`); it is built with `config_from` (`common/config_handler.py:403`), so a value `Config` refuses stops the run with `E0501` naming the field and the value (a popup rule by its name, `popup_rules['Rate Us'].action.type`) instead of falling back to a driverless default; `resolve_config_file` (`common/config_handler.py:90`) expands `$NAME` / `${NAME}` / `${NAME:-default}` and makes `./`/`../` values absolute, raising `E0501` for an unset variable or a missing file (output paths are exempt). It runs only where a config *file* is read (execute/dry_run, `live._config_from_yaml`, `doctor._load_project_yaml`), never in `Config`: `optics serve`/`optics mcp` build `Config` from request bodies, and resolving there would let a remote caller read the server's environment and probe its files. `optics configure --edit` reads without resolving, so saving keeps the references. A `devices` block (`DeviceEntry`, `common/config_handler.py:262`) gives each device identifier its own stack and `values`: an entry resolves as the top level does, its `values` take environment references only and must be text (YAML reads an unquoted `0123` as 83), and `Config` refuses an unknown key in an entry, a device without an enabled driver, two identifiers that differ only by case and a driver enabled at the top level beside the block. A `devices` key of another shape is not a block: every reader ignores it, as before the block existed. No entry point runs a block yet: `Session` drives one device and refuses a config that holds one, execute, dry run, live and generate stop with their own message, and `optics serve` refuses a start call that carries one. `optics configure --edit` saves the block as it was read. `Config.for_device` (`common/config_handler.py:385`) gives the config of one device, its entry laid over the top-level settings, and shares no list or mapping with another device's. `optics doctor` checks a block: `_project` (`helper/doctor.py:411`) builds one stack for each device (one unnamed stack for a project with no block), `validate_project` names each device's rows with its identifier (`PH1: appium settings`), and the machine checks cover what every device needs: each Appium address, a browser on this machine unless every Playwright device is remote, and the blocking hints of every device. A config with a block that `Config` refuses is one failing `config: file` row, and a `devices` key of another shape is an `info` row (`config: devices`).
   - `_load_test_cases` (`execute.py:789`) / `_load_modules` (`:798`) / `_load_elements` (`:801`) / `_load_api_data` (`:830`) read files via `CSVDataReader` (`common/runner/data_reader.py:342`) / `YAMLDataReader` (`:438`) into `ModuleData` (`common/models.py:154`) / `ElementData` (`:169`) / `ApiData` (`:298`). `_load_error_definitions` (`execute.py:836`) reads `error_definitions.csv` via `read_error_definitions` (`data_reader.py:418`) into `ErrorDefinitions` (`models.py:328`).
   - `_load_templates` → `discover_templates` (`execute.py:88`) collects images into `TemplateData` (`models.py:313`).
   - `_filter_and_build_execution_queue` → `filter_test_cases` (`execute.py:353`, see "Test case selection") + `build_linked_list` (`execute.py:499`), which threads `TestCaseNode → ModuleNode → KeywordNode` (`models.py:77` / `:42` / `:36`); per-test setup/teardown get their own `Setup (<test>)` / `Teardown (<test>)` nodes. Each node has a `CaseKind` (`models.py:20`): only a name ending with "Suite Setup", "Suite Teardown", "Setup" or "Teardown" wraps the tests (`case_kind`, `execute.py:374`), and a second one of a kind stops the run with `E0503`.

With no driver enabled, `session.driver` is `None`, and the run stops only if a reached module calls an `ActionKeyword`/`AppManagement`/`Verifier` keyword (`BaseRunner._needs_driver`).

6. `TestRunner.run_all` → `_process_test_case` (`:879`) → `_process_module` (`:814`) → `_execute_keyword` (`:473`):

This is **fallback level 1** (param-axis).
7. Every locate-based `ActionKeyword` action (`press_element`, `swipe_from_element`, `scroll_from_element`, `enter_text`, `enter_number`, `clear_element_text`, `get_text`, and through `press_element` the checkbox/radio/dropdown keywords; **not** `detect_and_press`/`*_until_element_appears`, which call `Verifier` directly) builds an `act(located)` callback and passes it to `ActionKeyword._locate_and_act` (`api/action_keyword.py:490`):

   - `_parse_aoi_param` (`:42`) normalises the `aoi` tuple; `_locate_element` (`:58`) calls the `strategy_manager.locate(...)` **generator** (`strategies.py:748`);
   - `_act_until_success` (`action_keyword.py:590`) pulls one result at a time, saves an annotated screenshot and calls `act(result.value)`, so a later strategy locates only after the earlier act fails. If every result's act fails with `E0105`, the driver itself refused the action, so that `E0105` is raised as is, with no self-heal. If every result fails otherwise **and** AI self-heal can't recover, it raises `OpticsError(Code.X0201, ...)`; if nothing was yielded, AI self-heal gets a chance too, and when it can't recover a new `Code.E0201` is raised with the strategy layer's error as its cause.
8. `StrategyManager.locate` (`strategies.py:939`) is **fallback level 2** (self-healing location):

   - Each strategy's static `supports(element_type, element_source)` (`:121`) gates it; `LocatorStrategy._is_method_implemented` (`:131`) skips stubs that only `raise NotImplementedError`.
   - `_try_strategy_locate` (`:894`) calls `locate(...)` (or `locate_with_aoi(...)` for a non-default AOI) and logs the attempt to `execution_tracer`. Results are yielded as `LocateResult(value, strategy, annotated_frame)` (`:776`); with none, it raises `OpticsError(Code.E0201, ...)` (`:785`).

The `act` callback (e.g. in `press_element`, `action_keyword.py:752`) presses a `(x, y)` tuple with `driver.press_coordinates`, else `driver.press_element(located_node, ...)`. `self.driver` is an `InstanceFallback[DriverInterface]` (`common/instance_fallback.py:12`) — **fallback level 3** (driver-axis); call sites try each enabled driver in `config.yaml` order. `_act_until_success` runs `act` inside `InstanceFallback.routed_to(owner)` (`instance_fallback.py:36`), so a result is only acted on by the driver that found it (a Playwright locator handed to Appium would "succeed" silently: its `click()` returns an un-awaited coroutine).
10. `TestRunner._send_event` (`test_runnner.py:402`) publishes `Event`s (`events.py:44`) to the session's `EventManager`; `JUnitEventHandler` (`common/Junit_eventhandler.py:192`) builds the XML and `TreeResultPrinter` (`common/runner/printers.py`) the live display. `--output` (`OutputMode`, `common/runner/event_stream.py`) picks the display: `auto` is `tree` on an interactive stdout and `plain` otherwise; `plain`/`jsonl` subscribe `EventStreamPrinter` (one flushed line per test case, module, keyword and acted-on popup event, and the first run failure); `none` (`--no-use-printer`, or `use_printer=False` from Python) shows nothing. `BaseRunner` resolves the mode once (`output_mode_for`). For `plain`/`jsonl`, `execute_main` and `dryrun_main` move console logs to stderr (`console_logs_to_stderr`), so stdout carries only progress; `run_project` leaves a Python caller's consoles alone. `PytestRunner` writes pytest's own report to stderr and captures at sys level, so the printer's stdout, bound before pytest starts, gets the lines live.
11. Before the suite teardown (a teardown often closes the app), or after the last test case, `TestRunner.run_all` (`test_runnner.py:1057`) calls `_capture_end_of_run_artifacts` (`:716`, see on-screen error detection). A failed suite setup skips every case but the suite teardown, and a failed test setup skips its test (`SetupGuard`, `test_runnner.py:162`, shared with `PytestRunner`, which skips with `pytest.skip`); a skipped case is a `NOT_RUN` test_case event, reported as `<skipped>` with the reason. `_note_failure` (`test_runnner.py:81`) keeps each failure's code on `Event.code`, which the report writes as `code` on `<failure>`, `<error>` and a failed `<kw>`; every `<testcase>` carries its `kind`. `_start_run` gives `JUnitEventHandler.plan_run` (`Junit_eventhandler.py:212`) every planned step, so steps and test cases that never ran are reported as `NOT_RUN`; a failed test case also gets screen + page source via `_capture_failure_artifacts` (`test_runnner.py:739`). `BaseRunner.cleanup` (`execute.py:991`) → `SessionManager.terminate_session` (`session_manager.py:209`) ends the driver and removes temp files and the `EventManager`; `ExecutionEngine._drain_events_and_shutdown` (`execution.py:363`) waits up to `OPTICS_EVENT_DRAIN_TIMEOUT_S` (default `2.0s`). `_run_until_stopped` (`execute.py:1075`) turns SIGINT into `KeyboardInterrupt` and SIGTERM into `SystemExit(143)` inside the running keyword so cleanup still runs (`PytestRunner` ends pytest there and raises the stop again after `pytest.main`), and `JUnitEventHandler._end_with_error` (`Junit_eventhandler.py:427`) marks the running test case `<error>`. A `StartProblem` from `_preflight` (`execute.py:610`) is passed to `plan_run` as `start_error` before `abort_with_panel`, so queued test cases are reported as `ERROR`. The suite name and every `classname` are `Config.name` (written by `project_config.write_project_config`, which every config.yaml writer uses: `optics init`, `optics configure` and `optics quickstart` keep the name the file held, else the folder's name with `$` escaped), else the project folder's name (`session_<id>` only without a project).

`dry_run` follows the same path with `DryRunExecutor` (`execution.py:89`) and `_process_test_case(..., dry_run=True)`. `_process_module` sends the same module events in both runs; a dry run only gives each keyword to `_dry_run_step` (`test_runnner.py:996`) in place of `_execute_keyword`. It resolves params via `resolve_param` (`test_runnner.py:328`, the *first* value, not the list) checks `keyword_map` membership, and binds the params to the keyword's signature (`E0403`) without calling methods — a known dry-run vs execute divergence. It builds no driver and no element source (`DryRunRunner.opens_devices` is false), so it needs no dongle, camera or server: its keyword table is `keyword_shapes` (`api/keywords.py:17`), the signatures of the `KEYWORD_SOURCES` classes with no session behind them. It cannot check locators, the app or the device, and says so at the end. Dry-run is a **validator**: an unknown keyword, an unresolved `${var}` or params that do not fit become a per-keyword `FAIL`, not an exception.

## Test case selection (`include` / `exclude`)

`--include` / `--exclude` (`_add_selection_arguments`, `cli.py:395`; `nargs="+"` + `action="extend"`) reach `BaseRunner.__init__`, which, when **either** is given, replaces **both** `config.include` and `config.exclude` (never merged). Python callers pass the same keyword args to `run_project`/`execute_main`/`dryrun_main`, where `None` means "use config.yaml".

Matching lives in `helper/case_selection.py` (`select_test_cases`, `:68`). `filter_test_cases` (`execute.py:353`) selects only regular cases; setup/teardown are always kept.
- Names compare after `" ".join(name.split()).casefold()`. `*` and `?` are the only wildcards; every other character, `[` and `.` included, is literal (not fnmatch).
- Include narrows first, then exclude removes.
- **Strict validation.** Every pattern must match a selectable case, else `OpticsError(E0702)` lists the bad patterns with "Did you mean" suggestions (a pattern that only hits setup/teardown is called out). An empty selection also raises `E0702`; a blank name raises `E0503`. The same rules apply to config.yaml, because a typo there used to silently run only the fixtures. `BaseRunner._exit_invalid_selection` shows the error (exit 3) before any session exists.

## On-screen error-detection journey

An auto-discovered `error_definitions.csv` (`error_code,match_string,description,severity`) is read by `_load_error_definitions` (`execute.py:836`) into `ErrorDefinitions` (`common/models.py:328`) on the `Session`. Once per batch run, before the suite teardown, `TestRunner._capture_end_of_run_artifacts` (`test_runnner.py:716`) saves a screenshot + page source (`_save_end_of_run_pagesource`, `:762`) and runs `_run_end_of_run_detection` (`:778`) with `extract_visible_text` (`common/error_detection.py:38`) and `detect_errors_in_text` (`:89`, case-insensitive **substring**, not regex). Matches become a synthetic failing JUnit testcase (`JUnitEventHandler.add_detected_errors`, `Junit_eventhandler.py:338`) and a failed `on-screen-error-detection` result, so the run exits `1`. The runner also publishes a `FAIL` `test_case` event for it, so the plain/jsonl lines name the error screen; its message is each match as `describe_detected_error` (`error_detection.py:83`) writes it (`code | severity | match_string | description`), the same text as the JUnit `<failure>`.

This is automatic. Library/Robot users get on-demand equivalents, `Add Error Definitions` (`optics.py:520`) and `Capture And Detect Errors` (`optics.py:562`), which exist **only** on the `Optics` facade, so the CSV/YAML runner, `optics serve`, `optics mcp` and `optics list` don't see them.

## Popup handling journey

Rules for popups are off until one is defined. A `popup_rules.json` found by `find_popup_rules` (`execute.py:146`) is merged into `Config.popup_rules` by `BaseRunner._load_popup_rules` (`execute.py:843`); library users call `Optics.add_popup_rules` (`optics.py:497`). Rules are `PopupRule` models (`common/models.py:377`); a rule that is not valid raises `E0501` naming the rule and the field (`invalid_fields`, `models.py:398`) wherever it comes from (`config.yaml`, `popup_rules.json`, `Optics.setup`, `Add Popup Rules`, `optics serve`). `permissions` is a sibling `Config` field whose names `Config` checks against `ANDROID_PERMISSIONS` (`common/permissions.py`). The guard reads the screen through `DriverInterface.popup_screen`, which a driver overrides to parse its own page source into a `PopupScreen` (`common/popup_screen.py`); `Appium` returns an `AppiumScreen` (`engines/drivers/appium_popup.py`), and any other driver keeps the `BlankScreen` default, so the guard does nothing there until it implements the hook.

1. `ActionKeyword._locate_and_act` (`api/action_keyword.py:490`) parses the AOI and index first, so a bad value is refused before the guard can press anything, then runs each pass through `_popup_step` (`action_keyword.py:544`): when any rule is set, it calls `PopupGuard.begin_step` once and `before_step` before each pass of the loop on `E0409` (popup dismissed), so a retry checks the before-every-step rules again. `_popup_before_self_heal` (`action_keyword.py:733`) asks `PopupGuard.on_failure` before each of the two `_ai_self_heal` calls in `_act_until_success`, so a popup is handled, retried or failed before an LLM can guess at it. After an act already ran and failed it never retries (`retry=False`): a retry could repeat what the act did. When a popup was dismissed there, self-heal starts from a new screenshot, or does not start if none can be taken. The `Verifier` keywords that read the screen (`assert_presence`, `assert_visibility`, `assert_text`, `is_element`, `validate_element`, `validate_screen`) run their look through `_assert_step` (`action_keyword.py:558`), which `build_keywords` gives the registered `Verifier`: a look that finds nothing asks `on_failure`, and after a dismissed popup the step looks again with its full timeout, because a look changes nothing. So `is_element` `invisible` passes only when `on_failure` finds no popup, and `validate_screen` and `is_element` raise a popup stop, or `E0601` for a rule whose module the session lacks, instead of reading it as absent. `ActionKeyword`'s own `Verifier` (`detect_and_press`, the dropdown and the scroll- and swipe-until loops) has no guard, so it cannot reset the step it runs inside.
2. `PopupGuard` (`common/popup_guard.py:139`) works on a `PopupIO` (`popup_guard.py:58`) of plain callables. A `module` action runs that module through the session's `FlowControl` with popup handling still on: its steps start their own step counts (the outer step's come back afterwards), and its own rule is skipped while it runs, so a module step is neither stopped by the popup it dismisses nor told it is unknown. A module the session does not have fails the step with `E0601`, not as a popup that stayed. `optics serve` sessions take modules as `modules_csv`/`elements_csv` or through `PUT /v1/sessions/{id}/modules`, parsed by the same `csv_rows` as project files, and `optics generate` hands the modules a rule reaches to the session with `Add Module`/`Add Element`. It reads the page source into a `PopupScreen` once for `before_step` and again for `on_failure`, because a popup may come up during the lookup, and it takes a new screenshot for each inspection. The `PopupScreen` also takes the iOS system alert that `Appium.read_alert` (`engines/drivers/appium.py:640`) returns, because iOS leaves it out of the page source. The first rule in the list that matches wins; the guard acts (`tap` is resolved from the page source's own bounds before the locate ladder, `_popup_tap` at `action_keyword.py:717`), re-reads until the popup is gone, and returns an `Outcome`. It never presses for a `sensitive` rule or an unknown popup.
3. A stop raises `E0206` (unknown popup, an element-location code, so each `${var}` value runs the guard again), `E0407` (a limit) or `E0408` (stayed, `fail_step`, `stop_run` or sensitive). The E04xx ones do not advance the fallback ladder. `E0408` with `stop_run` also sets `PopupRun.stop` (`popup_guard.py:119`).
4. The runner owns the `PopupRun`; `TestRunner.run_all` and `test_context.case_scope` (the pytest runner, per case) bind it in `test_context.popup_run` and restore the earlier value afterwards; `_publish_popup_events` (`test_runnner.py:533`) publishes each inspection as a `popup` event through `popup_event` (`test_runnner.py:204`), and `SetupGuard.stop` (`test_runnner.py:173`) skips the cases not started, except the suite teardown. The run's summary is logged at the end of `run_all`.
5. `Appium.apply_permissions` (`appium.py:609`) sets `permissions` after a new session starts or is attached to (Android: `mobile: changePermissions`, with `autoLaunch` held off until they are set so no prompt comes first, unless the caller already turned it off or `autoWebview` needs the app open; an unknown permission name is refused when the `Config` is built, before any session starts; iOS: not applied, a warning points to the `autoClickAlertSelector` capability the user puts in the capabilities); `answer_alert` (`appium.py:651`) is the iOS `alert` action.

Evidence (`popup_<run id>_<n>_before.png`, `_after.png`, `_source.xml`) is written through `utils.save_capture_image` and `save_capture_text`; screenshots need a screenshot element source, which `appium_find_element` is not.

## Live session journey (`optics live`)

`optics live` runs keywords against a running target without a test folder. It is a **separate path from execute** (no `ExecutionEngine`, `EventManager` or JUnit) but reuses the keyword and element machinery.

1. `cli.py:528` `LiveCommand` → `live_main(folder_path)` (`helper/live.py:1511`); `LiveArgs` (`cli.py:535`) is the args model.
2. `_compose_config` (`live.py:264`) builds a `Config` from the project folder (`_config_from_yaml` / `_load_partial_config`, `:209`/`:238`). Whichever single driver is enabled wins (`_enabled_drivers`, `:254`); no driver is hard-coded.
3. `LiveController.__init__` (`live.py:321`) creates a `Session` via `SessionManager`, and `_build_registry` (`:446`) calls `build_keywords`, as `RunnerFactory.create_runner` does. Live executes through the API layer, so it gets self-healing, AOI and screenshots for free.
4. `run_keyword` (`live.py:547`). Live builds its candidates and args with the runner's `step_candidates` and `step_arguments`, passing `_undefined_element` (`live.py:310`) so an undefined `${name}` fails as `E0901`, and runs them through the shared `fallback.run` in `_attempt_combos` (`:646`), so level 1 behaves as in the runner. `_run_single_combo` runs under `keyword_outcome.capture()`, so an error the keyword logs without raising fails it as `E0401`.
5. **Natural-language mode** — `NaturalLanguageAgent` (`common/nl_agent.py:243`) is a bounded loop (`max_steps`, default 15) over one `agent_core.AgentSession` per run (`run`, `nl_agent.py:259`; each session call runs in its own `asyncio.run`, so `run` raises inside a running loop). 6. A name collision raises `SaveConflictError` (`:172`) unless `allow_append=True`.

## MCP server journey (`optics mcp`)

`optics mcp` exposes the keywords over MCP. It is a **thin in-process wrapper over `common/expose_api.py`**: it does only transport and rendering, never its own session or execution logic. The agent logic lives in three core modules that the NL agent shares:
- `common/agent_core.py`: `AgentSession` (`agent_core.py:777`), built from async `read(png)` and `run(keyword, params)`, with the `RefTable`, the steps and a `Recorder` (`agent_core.py:649`). `AgentSession.act` (`agent_core.py:900`): `prepare` (`agent_core.py:593`; resolves the target and builds keyword calls, raising `Fail` for `stale_ref`, `unknown_ref`, `ambiguous`, `invalid_params` or `no_locator`; an agent's `${name}` may fill only a locator or a text-entry keyword's typed text, so a page-influenced reply cannot put a session value into a URL or script) → loop guard → calls (`session_lost` raises at once) → settle (after a non-typing success, at most 2 extra reads 0.6 s apart until two reads agree; a screen with no rows is re-read while loading; read-only keywords read once, `_waits_for_change`) → `screen_snapshot.verify`, polled for up to `EXPECT_WAIT_S` while an expectation is unmet → `Recorder.add`.
- `common/screen_snapshot.py`: `Row` (its `state` shows what a control holds: `= "x"`, `(checked)`/`(unchecked)`, or `(filled)` for a secret, from the `value`/`checked`/`filled` keys that `BOUNDS_JS` and `UIHelper._compact_entry` add; a state change is a changed row in `diff`), `listed_added` (a diff reply lists at most `DIFF_ROWS` added rows, controls first, and `REMOVED_ROWS` removed rows), `RefTable` (`screen_snapshot.py:403`), `diff`, `verify` (`screen_snapshot.py:549`), `ladder` (`screen_snapshot.py:656`; `act` acts now, `save` is recorded, `replay` is what a replay uses) and `is_secret` (`screen_snapshot.py:674`). `RefTable.snapshot` keys each row statelessly by `_identity` (a native id that no other row has, else a unique positionless locator plus nearby context, else bounds/class/label; a window title is never context and a field has one key empty and filled, so text that changes around a control does not move its ref) and keeps a session-long key-to-ref map, so a ref survives overlays, filters and relabels and returns on an earlier screen. A row read by OCR (`"ocr": True`) is keyed by its letters and digits (symbol-only text by itself), since camera frames move OCR boxes; it keeps its earlier text when a new read differs only by case or a punctuation mark read as another (`_same_reading`).
- `common/keyword_outcome.py`: collects one keyword run's outcome in a ContextVar (`capture`, `keyword_outcome.py:70`): the winning strategy and the first ERROR logged on `optics.internal` without a raise (`asyncio.to_thread` carries the ContextVar along).

1. `cli.py:MCPCommand` → `run_mcp_server(transport, host, port, toolset)` (`helper/mcp_server.py:1347`); `MCPArgs` (`cli.py:185`): `--transport {stdio,http}` (default stdio), `--toolset {core,full}` (default `OPTICS_MCP_TOOLSET`, else `core`). `optics mcp install` calls `mcp_install.install(toolset)`: it adds a user-scope entry with an absolute command, then removes this folder's local entry, and names any project or other-folder entry that still wins.
2. `build_server(toolset)` (`mcp_server.py:1148`) builds a `fastmcp.FastMCP` with `SERVER_INSTRUCTIONS` (`mcp_server.py:154`, about 2,000 characters). Every tool carries all four MCP annotations (`_annotations`, `mcp_server.py:245`), and each core tool has a lean input schema and no output schema (it replies with text and, for a screenshot, an image).
   - **Core (default)** — `start_session`, `terminate_session`, `observe`, `tap`, `type_text`, `scroll`, `press_key`, `launch_app`, `batch`, `check`, `run_keyword`, and `send_feedback` unless the user opted out (see "Update notice and agent feedback"). `batch` (`_batch`) runs several tap/type/key steps under one lock through `AgentSession.act`, stops at the first failure and replies with the diff from before the first step. Acting tools go through `_act` (`mcp_server.py:766`) → `_guarded` → `AgentSession.act`, and `_step_reply` (`mcp_server.py:746`) renders the `Step` as short text, the whole reply: Claude Code shows `structuredContent` in place of the text, so the core tools send none, and a keyword tool that returns a dict sends the same JSON as its text. `run` is `_run` (`mcp_server.py:664`): `expose_api.execute_keyword` under `keyword_outcome.capture()` (a logged error without a raise becomes `E0401`, `silent_failure`). `verified` is `pass|fail|unknown`; an unreadable screen gives `unknown`, and an action whose target was not named exactly and was found by OCR or image is never `pass`. The loop guard refuses an action when the last three steps since the last `observe`/`check` had the same `attempt_key` (`agent_core.py:621`) and made no progress. `check` (`_check`, `mcp_server.py:861`) calls `AgentSession.check` (`agent_core.py:960`). `observe` (`_observe_screen`, `mcp_server.py:889`) issues refs. `run_keyword` (one misnamed param is taken as the one required param still missing, in `agent_core.bind`) reaches every keyword in `keyword_catalog` (`agent_core.py:281`; coordinate keywords only with `OPTICS_MCP_ALLOW_COORDINATE_TAPS=1`, see `_reachable` (`mcp_server.py:265`)), expands refs to live locators and clamps timeouts to 60 s.
   - **Full** — the older surface: one string-typed tool per public `ActionKeyword`/`AppManagement`/`Verifier` method (`_make_keyword_tool` (`mcp_server.py:922`), defaults via `_stringify_params` (`mcp_server.py:240`), `agent_core.RESOURCE_KEYWORDS` excluded), `screenshot`, and the non-clashing core tools (`scroll` and `launch_app` stay keyword tools).
   - **`start_session`** — without `elements_sources`, `_default_sources_for_driver` (`mcp_server.py:87`) fills the driver's sources (`ElementSourceFactory.available_sources`, ranked by `_SOURCE_RANK`); an explicit empty list is kept. An entry is a source name or a config.yaml entry (`{"camera_screenshot": {"capabilities": {...}}}`), so a local caller sets a webcam's `camera_index`, `find_screen` and `rotation`; `_refuse_server_side_reads` still refuses a remote caller's camera. With `app`, it also launches it.
   - **Resources** (each with an explicit `mime_type`) — `optics://keywords` (what the `run_keyword` enum accepts, as `{keyword, params, about}`; with one session open it leaves out `_Slot.unsupported`, and `run_keyword` refuses those keywords as `unsupported`), `optics://project-format`, `optics://browser-profiles` (local Chrome/Edge profiles; only a stdio server lists them or accepts a caller's `capabilities.profile`, via `expose_api.server_reads_allowed` and `_refuse_server_side_reads`; a caller's `user_data_dir` is always refused), `optics://session/{session_id}/{screenshot,source,elements,screen_elements}` and `optics://session/{session_id}/steps` (`_steps`, `mcp_server.py:911`): steps plus `modules_csv`/`elements_csv` from `Recorder.csv` (`agent_core.py:717`). An ended session's steps stay readable by its owner: in memory (`_ENDED`), and for a stdio caller also in `$OPTICS_HOME/mcp/steps/<id>.json` (`_save`), written after each call and on shutdown, so they outlive a server restart; files older than 7 days are pruned. The Recorder writes element params as `${name}` with `ladder(...).save` rungs and params as the CSV runner binds them (`agent_core.runner_params`). A typed value is secret when `is_secret` marks the target row or the field `agent_core.Focus` holds, judged on the screen before the typing; with no held field, or one that is not an input, any secret field on the screen counts (and a raw XPath/CSS locator that names no row counts when the screen has a secret field). Secret values are saved as a `<field> value` element written as `<redacted>`, and a secret input's label is never its element name. `optics live` shares the same `Focus`.
3. **Per-session state** — `_Slot` (`mcp_server.py:305`) holds the `AgentSession`, an `asyncio.Lock`, a `busy` flag, `last_used` and its `owner`: a session belongs to the MCP client connection that started it (`_caller`), and every tool and resource looks it up through `_owned`, so another client can neither use it nor see its id. `_slot` (`mcp_server.py:600`) picks the only open session when `session_id` is empty (`_start` ends a session whose slot could not be built, so none keeps a browser), after `_sweep` (`mcp_server.py:544`) ends other callers' sessions idle past `OPTICS_MCP_SESSION_IDLE_S` (default 900, `0` off). `_guarded` (`mcp_server.py:613`) serialises calls, caps each at `OPTICS_MCP_CALL_TIMEOUT_S` (default 100) and keeps the session busy until a timed-out driver call ends. `_driver_read` (`mcp_server.py:652`) holds `keyword_lock` around screen reads.
4. **Procedures by link, not by tool**: a skill is the procedure for one whole task (a migration, a suite from a session, a failed run, CI, a device setup), and each one is a page of the site (`.well-known/agent-skills/<name>/SKILL.md` in the optics-framework-org repo), so it costs no tokens until an agent needs it. `SERVER_INSTRUCTIONS` ends with one line that sends an agent to the site's `skills.md` before a whole task. A reply carries the link of one skill at the moment it applies: a `start_session` that cannot start names the setup skill of its target (`_setup_lines`, `mcp_server.py:385`), and `terminate_session` names `write-a-suite` when the session recorded steps; `optics://project-format` ends with the link of `skills.md`. `_fail_lines` adds a page from `_DOCS_PAGES` to the `Next:` line of the failure kinds a page helps with. The server never fetches a link, the links live only in `mcp_server.py` (`agent_core` is shared with NL mode), and a skill name that a release links stays on the site. Put what an agent needs on every turn in the instructions or a tool schema, and what only some sessions need in a skill. No model read a resource unprompted in the benchmark, and a docs tool would cost schema tokens on every turn.
5. **Errors are tool results**: `as_fail` (`agent_core.py:233`) maps exceptions to a `Fail` (`agent_core.py:114`) with a kind, the optics code, one fact line and a `Next:` line from `agent_core.ADVICE`. `E0101`/`E0103`/`E0106` end the session through `_end` (`mcp_server.py:528`); `E0102` does not. Only the full toolset still raises `ToolError`.
6. `fastmcp` is the optional `mcp` extra; imports are guarded (`_require_fastmcp`).

**Deliberately tool-light.** There are **no** recording, suite-CRUD, replay, device-discovery or `doctor` tools: an agent builds a suite from the `steps` resource and `optics://project-format` and runs it with `optics execute`. The MCP layer never shells out to `adb` or assumes a device type; the earlier `mcp_authoring.py`/`mcp_diagnostics.py` modules (~24 tools) were removed for this reason.

`optics mcp` and `optics serve` have separate `SessionManager`s, so sessions are **not shared**; stopping `optics mcp` (including SIGTERM) ends its sessions.

## Update notice and agent feedback

Both reach optics-framework.org with the User-Agent `optics/<version> (<surface>; <os>)` (`updates.user_agent`), which the site's analytics count as their own client. `DO_NOT_TRACK` set to anything but an off value turns both off (`turned_off`, `helper/updates.py:33`).

- **Update notice.** `refresh` (`helper/updates.py:91`) reads the newest version from PyPI and each release's headline from the site's `release.json` at most once a day, into `$OPTICS_HOME/update.json`; `notice_lines` (`helper/updates.py:153`) says a newer release is out with the headlines of the skipped releases, or, once after an upgrade, what this release added. Off with `OPTICS_NO_UPDATE_CHECK` or in `CI`. Surfaces: `main` starts `refresh_in_background` and `_print_notice` (`cli.py:681`) writes to stderr after the command, only on a terminal and not for `_OWN_NOTICE` (`cli.py:678`); `check_release` (`helper/doctor.py:131`) adds a doctor row; `optics live` prints it on quit; `optics serve` logs it at start; an MCP `start_session` reply carries it once per server process (`_update_line`, `mcp_server.py:341`). Add a `release.json` entry on the site with each release.
- **`optics upgrade`.** `UpgradeCommand` (`cli.py:299`) → `updates.upgrade`, which always asks PyPI for the newest release through `lookup` (`helper/updates.py:99`), in `CI` and with `OPTICS_NO_UPDATE_CHECK` too, because the user asked; `DO_NOT_TRACK` only skips the site's headlines. When PyPI does not answer, it says so and upgrades to whatever the installer finds, never trusting the cache. It then runs `plan_upgrade` (`helper/environment.py:323`): a uv or pipx tool upgrades itself, a lockfile-managed project and a Windows tool get the command to run, and anything else goes through `plan_install`.

Failure kinds where Optics may be at fault (`_FEEDBACK_KINDS`, `mcp_server.py:148`) and `terminate_session` point to the tool. Off with `OPTICS_NO_FEEDBACK`, which also removes the tool. The site caps reports per day and files a daily digest in a private repository; the endpoint lives in the optics-framework-org repo.

## Mobile web journey (Appium: browsers and WebViews on Android and iOS)

Web pages on a device run through the **same Appium session** as native apps, with no browser driver and no context-switch keyword. The session stays in `NATIVE_APP`, so native locators and OCR keep working on web pages and an app that taps a link continues in the browser. End-to-end tests: `tests/integration/test_appium_app_to_browser.py` (emulator in `OPTICS_E2E_EMULATOR`; clears Messages and Chrome data) and `tests/integration/test_appium_ios_app_to_browser.py` (simulator in `OPTICS_E2E_SIMULATOR`).

1. **Web locators** (`css=…`, bare CSS, DOM XPath) reach `AppiumWeb` (`engines/elementsources/appium_web.py`). `AppiumWeb.locate` (`appium_web.py:99`) returns `None` for text, image and native XPath, and queries only the DOM branches of an XPath union (`utils.web_xpath`, `common/utils.py:426`) and acts only while `Appium.native_ui_platform` (`appium.py:403`) is Android or iOS: an iOS `browserName`/`autoWebview` session already reads the page natively, and `web_context` would drop it to `NATIVE_APP`.
2. `Appium.web_context` (`engines/drivers/appium.py:1965`) enters the page and always switches back to `NATIVE_APP`. **iOS** (`_enter_ios_web_context`, `appium.py:2011`): tries `com.apple.SafariViewService` pages first, then pages of the app in front, and takes the first visible page that holds a locator (`_page_holds`); a page that times out goes into `_frozen_web_contexts` until its URL or title changes. `_IOS_CONTEXT_OPTIONS` (`appium_platforms.py:67`, native sessions only) lists every app's pages and bounds the waits (an ad-hoc app's inspector bundle id is `process-<Name>`). **Android**: the first entry goes through `_foreground_web_context` (`appium.py:2073`) and `_context_name` (`appium.py:182`; the switchable name is `webviewName`, not `webview`); `_focus_window` (`appium.py:2090`) picks the tab showing that URL from `Target.getTargets`, because `switch_to.window` brings a tab to the front. A `browserName` session names Chrome `CHROMIUM`, not `WEBVIEW_chrome`. Later entries use `_reenter_web_context` (`appium.py:2055`), since `mobile: getContexts` waits 2 s on every frozen app's DevTools socket; `_ANDROID_CONTEXT_OPTIONS` (`appium_platforms.py:59`) keeps context switches off those sockets.
3. The element is scrolled into view, must be `is_displayed()`, is uncovered by `AppiumWeb._uncover` (`appium_web.py:134`) and measured by `Appium.web_element_screen_rect` (`appium.py:2132`). `_web_transform` (`appium.py:2151`) maps CSS pixels to the screen by finding an injected invisible probe natively, so toolbars, zoom, the keyboard and several WebViews are all accounted for (scrolled-out elements are not in the accessibility tree, so the probe, not the element, is measured). The probe must sit inside an on-screen WebView, so a page cannot place a tap outside its own view (`E0201`). `AppiumWeb._settled_rect` (`appium_web.py:144`) waits out toolbar animation. `locate` returns a `ScreenPoint` (`common/elementsource_interface.py:7`): an `(x, y)` tuple that also carries the text, `covered` and `enabled`/`checked` state that `Verifier.is_element` reads. A tap on a covered element is refused (`E0201`); only `Get Text` passes `allow_covered=True`.
4. `AppiumWeb.check_elements` (`appium_web.py:165`) is the assertion loop's one look; `assert_elements` (`appium_web.py:151`) wraps it. Sources declare lookups via `ElementSourceInterface.can_locate` (`common/elementsource_interface.py:82`), and strategies skip elements whose `can_assert` is false, so a `css=` assert never queries native sources and a text assert never enters the web context. Native sources decline DOM-only XPaths (`utils.is_dom_only_xpath`, `common/utils.py:398`).
5. **Screen elements.** `AppiumWeb` sets `SUPPLEMENTS_SCREEN_ELEMENTS` (`common/elementsource_interface.py:40`), so `StrategyManager.get_interactive_elements` (`strategies.py:1256`) merges the page into the native list via `merge_screen_elements` (`strategies.py:627`), dropping native entries a web entry mirrors and keeping containers (`_native_container`, `strategies.py:617`). `AppiumWeb.get_interactive_elements` (`appium_web.py:65`) uses the `WebDomInspector` (`engines/elementsources/playwright_page_source.py:281`) that Playwright shares, so both list the same nodes and locators. `_inspect_nodes` (`appium_web.py:73`) runs `BOUNDS_JS` (`playwright_page_source.py:45`) and `SUGGEST_LOCATORS_JS` (`playwright_page_source.py:101`) in one script; off-viewport nodes are listed with `offscreen: true`. Each row's `loc` is checked in the live DOM to match only that node and avoids generated ids and digits, so it is stable across runs.

`browserName`/`autoWebview` sessions start in the web context; `Appium._create_new_driver_session` (`appium.py:502`) moves Android ones to `NATIVE_APP`. `Appium.launch_app` (`appium.py:1115`) opens a URL or deep link. Given a package or bundle id, `launch_app` and `launch_other_app` wait for the app to reach the front (`_wait_until_in_front`, `appium.py:1523`): another app still in front after 5 s, or a front app that no read in those 5 s could get, fails the step with `E0401`. Only an Android prompt from a package in the popup guard's `ANDROID_SYSTEM_PACKAGES` or an iOS system alert counts as launched (`_shows_system_prompt`, `appium.py:1519`); a vendor's own permission screen does not. A session that `launch_app` starts, with or without an app named, is activated only when another app, not a system prompt, is in front (an attached session, or `autoLaunch` off); a URL launch checks no app. The preflight only checks local `adb` devices when the server is local (`_is_local_server`, `helper/execute.py:652`).

## TV web app journey (Appium: Tizen and webOS)

A Tizen or webOS app is a web page with no native tree and no touch. Both profiles set `PlatformProfile.web_ui` (`engines/drivers/appium_platforms.py`), read by `Appium.is_web_ui` (`engines/drivers/appium.py:410`).

1. **Lookup.** `AppiumFindElement._query` (`engines/elementsources/appium_find_element.py:102`) accepts `css=` and turns a text locator into `utils.dom_text_xpath` (`common/utils.py:310`).
2. **Dispatch.** `press_element`, `enter_text_element`, `clear_text_element` and `get_text_element` carry `@_on_tv` (`engines/drivers/appium.py:254`) above `@supported_on(*POINTER)`, which calls the same method on `TvWebApp` (`engines/drivers/appium_tv.py:263`, one per session via `Appium._tv_app` (`appium.py:426`)). Other phone and desktop methods raise `E0105`.
3. **Focus.** `TvWebApp.focus` (`appium_tv.py:309`) reads focus from the DOM after each key press; `_Route` (`appium_tv.py:224`) picks keys toward the target. `press_element` is focus plus ENTER.
4. **Typing.** A real `<input>` gets `send_keys`; an app-drawn field is typed key by key on the on-screen keyboard by `_type` (`appium_tv.py:375`). The field is checked before and after: a mismatch, or any error after the first key, raises `E0405`, so no fallback types the text again.
5. **Screenshots.** Tizen sets `native_screenshot=False` (an Appium screenshot hangs the session), so projects use `camera_screenshot`.

TV chromedrivers are old (Tizen 5.5: Chrome 69; webOS 4: Chrome 53): JS must be ES5, script arguments use the legacy `ELEMENT` key, and nothing calls the element rect endpoint. A remote press costs about a second.

## Bluetooth journey (`ble` driver on airhand)

The `ble` driver drives a phone, tablet, computer or TV that has nothing installed, through an [airhand](https://github.com/chinmayajha/airhand) dongle: a Bluetooth keyboard, mouse and media remote on USB serial. The protocol, retries and refusals live in the `airhand` package (the `ble` extra); Optics keeps only the mapping.

1. `BLEDriver` (`engines/drivers/ble.py:190`) validates `Capabilities` (`ble.py:127`: `platform`, `frame`, and `serial` or `port` or neither for the only plugged-in dongle) and opens `airhand.Dongle`; with `host` (a paired device's Bluetooth name or address) it calls `Dongle.use`, so only that device holds the link, and a host the dongle cannot choose stops the session with `E0501`. `PLATFORMS` (`ble.py:95`) holds each platform's select-all, Back, launcher shortcut or Android app-drawer key, which `Scroll` directions turn the wheel (`Platform.wheel`; iOS only up and down, with the sign reversed and the pointer over the middle of the screen) and which drag (Android for `Platform.scroll_ms`, slowly, because Android flings content on by the release speed), and where the App Switcher shows the last app (`force_terminate_app` (`ble.py:377`) opens the app and flicks that card away; Android opens Recents with Meta+Tab); `supports` hides `go_back`/`launch_app` where the platform has none. Android sets `finger`: the dongle opens in touch mode (airhand 0.1.2), because Android ignores a mouse's absolute position.
2. Positions go to the dongle as fractions of `frame`; vision matches are in camera pixels, so `frame` must equal the camera's `out_width` × `out_height`. `_drag` (`ble.py:580`) keeps touch drags at `MIN_DRAG_SPEED`, because iOS takes a slow drag for a tap. On iOS `_park` (`ble.py:587`) moves the pointer to the status bar after every tap, drag and wheel scroll, so it does not hide the next target from the camera; a refused move is logged, so the touch is not tried again. `press_keycode` (`ble.py:327`) sends media keys as consumer reports and everything else as a key combination. A webcam's `camera_screenshot` finds the screen's corners with `find_screen` (`engines/elementsources/screen_finder.py`): `brightness` presses the driver's brightness keys and keeps what changed, `pointer` shows the driver's pointer (`DriverInterface.point_at`; the `ble` driver on every platform but Android, whose pointer is relative) on a grid and fits the corners to where the camera sees it (`screen_finder.pointer_corners`), so a screen dark to its edges is found too; `auto` tries `brightness` (and one frame), then `pointer` when no lit screen is found and the driver shows a pointer; a `ViewGuard` compares the area around the screen at each capture to catch a moved phone. Without a webcam, `usb_screenshot` (`engines/elementsources/usb_screenshot.py`) reads a phone on USB with `adb` or `devicectl` and takes its platform from the driver's `DriverInterface.device_platform`; it never acts, so taps stay with the dongle, and `check_usb_screen` (`helper/doctor.py`) checks the tool, the one attached phone and that the screenshot size equals `frame`. A `camera_index` opens through `open_webcam` (`engines/elementsources/webcam.py:167`): where macOS refuses this process the camera (`camera_access`, `webcam.py:49`; a stdio MCP server under Claude Code's desktop helper, which lacks the camera entitlement, so macOS never asks), it starts a `WebcamReader` (`webcam.py:192`) through launchd, which reads the webcam in its own process, so macOS asks once for this environment's Python, and sends raw frames over a private Unix socket. A webcam's autofocus hunts on a screen, so `CameraScreenshot._focus` (`engines/elementsources/camera_screenshot.py:313`) turns it off and holds the lens where the screen is sharpest (`camera_lens.sharpest`, `engines/elementsources/camera_lens.py:40`), first on the whole frame, then on the screen once it is found, and a new session first confirms the value it saved for that camera model in `$OPTICS_HOME/camera_focus.json` (`camera_lens.saved_focus`) with three looks; on macOS the lens is set by UVC requests through IOKit (`camera_lens.uvc_lens`), and a view with no clear peak gives focus back to the camera. A lens whose first sweep never sharpens the view may be another camera's (`uvc_lens` cannot tell which one `camera_index` opened), so it is not used again; a released lens sets the camera's focus mode back.
3. `Launch App` runs the methods of `Capabilities.launch_methods` (`ble.py:175`; `launch` in config.yaml, else the platform's default: on phones the system search or app-list search, then `home_icon`, then on Android `drawer_list`, which scrolls the app list until the app's label shows) in `_open_app` (`ble.py:423`), and tries the method that last opened an app first. Each method is a generic key-and-tap sequence, never a vendor path. `AppManagement.__init__` (`api/app_management.py:20`) hands every driver a screen reader through `DriverInterface.attach_screen` (`common/driver_interface.py:345`): `StrategyManager.get_interactive_elements` when a source sees the screen and OCR is set, else `None`. With a reader, `_launched` (`ble.py:457`) requires the name twice after typing (the query and a result, `_labels`) and both gone from their places after Enter, and goes Home before the next method; all failing is `E0405`. When `drawer_search` types into no field and the app-list key opened a screen of its own (`_overlap` with the home screen's text), `_launched_from_search_box` (`ble.py:472`) taps the text alone on its line nearest the list's top or bottom edge (`_search_box_at`, `ble.py:677`) and types again, so no launcher needs `app_search`. Without a reader, only the first method that needs no camera runs, unchecked.
4. `_mapped` (`ble.py:612`) turns airhand errors into codes: `DongleLost`/`HostUnavailable` → `E0106`, `WrongFirmware` → `E0501`, `Unsupported` → `E0403`, any other → `E0401`.
5. Surfaces: `check_ble` (`helper/doctor.py:560`) reads the dongle, the paired hosts (matched with `airhand.find_host`, as `Dongle.use` matches them) and the link state, `check_usb_screen` checks a `usb_screenshot` source's tool, device and screenshot size (with or without a `ble` driver), and `_source_row` (`doctor.py:509`) accepts `camera_screenshot` for any driver; `_ask_bluetooth` (`helper/project_config.py:112`) asks the configure/quickstart questions; `_session_config` (`helper/mcp_server.py:996`) gives an MCP ble session the server's camera (`WEBCAM_SCREENSHOT_URL`, `_camera_source`) at the frame size, with a local OCR engine and `templatematch` unless the caller names engines (a `camera_screenshot` the caller names gets the same; `_sized_camera` swaps the size when the caller's settings rotate the frame); `_refuse_server_side_reads` (`common/expose_api.py:311`) refuses a remote caller's `port`, a `serial` that no plugged-in airhand dongle has, and any `usb_screenshot`.

## Element location pipeline (deep dive)

- **`StrategyManager`** (`strategies.py:611`) — one per `ActionKeyword` and `Verifier`. It owns `locator_strategies` (`StrategyFactory`, `:738`), `screenshot_strategies` (`ScreenshotFactory`, `:768`; rejects black screens) and `pagesource_strategies` (`PagesourceFactory`, `:760`), built per instance of the element-source `InstanceFallback`, so several sources multiply the list.
- **OCR screen rows** — with no pagesource strategy and no supplement, `StrategyManager._read_text_rows` (`strategies.py:1224`) lists what `TextDetectionStrategy.screen_elements` (`strategies.py:318`) reads: one tappable `Text` row per OCR result at or above `OCR_ROW_MIN_CONFIDENCE`, in window coordinates. So `observe`, `check`, the NL agent and `failed_steps_elements.json` work with a camera. A row's `ocr_index` is its place among `find_text`'s matches for its text, so a tap with that index hits that row, and "Stop" never lands on "Stopwatch". A row whose text matches more than once carries that place as `Ladder.index`; only a tap passes it on, as `press_element`'s `index`, and `prepare` and self-heal's `_bind_target` refuse it (`no_locator`).
- **`StrategyFactory.create_strategies`** (`:507`) filters by `supports` and sorts by priority: XPath(1) < TextElement(2) < TextDetection(3) < ImageDetection(4).
- **`StrategyManager.assert_presence(elements, element_type, timeout, rule)`** (`:707`) backs `Verifier.assert_presence` (`api/verifier.py:238`). `_assert` (`strategies.py:990`) owns the deadline and polls in rounds (`_assert_round`, `:1049`), giving each strategy one non-waiting `check_elements` call on pending elements until the rule (`any`/`all`) is met. Vision strategies share one screenshot per round, run less often while a cheaper strategy still looks, and skip an unchanged screen; a strategy that raises is dropped. `ElementSourceInterface.check_elements` (`common/elementsource_interface.py:107`) defaults to the source's `assert_elements` with a 1 s timeout.
- **OCR text matching** is one rule for every engine and for locate and assert: `find_text` (`common/text_match.py:257`) matches tokens in sequence (a token is a word, or one character of a script without spaces), on one line or wrapped onto the next, ignoring case and the spaces between words (right-to-left text placed by the Unicode bidirectional rules). With `strict` (`Config.strict_element_match`, read by `TextDetectionStrategy._strict`) only whole tokens match; otherwise a part of a word does too, listed after the whole-word matches. Each group is sorted by row, then left edge. `TextInterface.find_element` (`common/text_interface.py:64`), `match_and_annotate` (`engines/vision_models/base_methods.py:65`) and `TextDetectionStrategy.screen_elements` all call it, so an engine only implements `detect_text`.
- **`LocateValueWithFrame`** (`:22`) is the vision return shape `(value, annotated_frame)`; `annotated_frame` is saved by `_save_annotated_for_result` (`action_keyword.py:70`).
- **AOI** — `TextDetectionStrategy.locate_with_aoi` (`:267`) and `ImageDetectionStrategy.locate_with_aoi` (`:474`) crop to the area of interest and map coordinates back; used only when `aoi_x/y/width/height` differ from `0/0/100/100`.
- **`execution_tracer`** (`common/execution_tracer.py`) is called from `_try_strategy_locate` and the assertion loop (at most once per strategy per assertion). Read it to see which strategy worked.
- **`keyword_outcome` hooks** — `ExecutionTracer.log_attempt` (`execution_tracer.py:11`) calls `keyword_outcome.looked` (`keyword_outcome.py:46`, drops errors logged before the lookup and keeps the first strategy that found the element); `_act_until_success` calls `act_failed` (`keyword_outcome.py:56`, drops a failed act's errors) and `acted` (`keyword_outcome.py:62`, which keeps errors so one logged after a successful act still counts as silent).

### Four fallback layers — keep them straight

| Level | Where | Iterates over | Trigger to advance | When exhausted |
|------|-------|---------------|---------------------|----------------|
| 1 — param | `fallback.run` (`common/fallback.py:98`) | Cartesian product of `${name}` value lists from `ElementData`, at most `MAX_ATTEMPTS` | `fallback.advances`: `is_element_not_found`, which is `E02xx` or `X0201` | `FallbackExhausted`; the runner reports it in `_handle_keyword_failure` (`test_runnner.py:638`) |
| 2 — strategy | `StrategyManager.locate` (`strategies.py:939`) generator | XPath → Text → OCR → Image | strategy yields no result | raises `OpticsError(Code.E0201, ...)` (`:775`) |
| 3 — driver / source | `InstanceFallback.instances` (`instance_fallback.py:14`) | Enabled instances in `config.yaml` order (`act` is pinned to its owning driver via `routed_to`) | call-site `try/except` per instance | call-site raises (varies) |
| 4 — AI self-heal | `ActionKeyword._ai_self_heal` (`action_keyword.py:322`), backed by `AISelfHealHandler` (`common/ai_self_heal.py:304`) | Up to `max_steps` (default 5) LLM-driven keyword calls | the call doesn't complete the goal | `give_up`, an error or the budget — the original `E0201`/`X0201` is raised |

The chains are independent; `Code` tells level 1 which ladder raised.

**Level 4 — AI self-heal (opt-in).** When level 2 exhausts inside `_act_until_success` (`action_keyword.py:590`), it calls `self._ai_self_heal(...)` (`:322`) before raising. One exit skips it: when every located result's act fails with `E0105`, `_after_failed_acts` re-raises that `E0105`, since no other element or heal can do an action the platform does not have. It is **inert unless enabled**: `Config.ai_self_heal: bool = False` (`config_handler.py:240`) *and* a working `llm_models` entry (`_ai_self_heal_ready`, `action_keyword.py:370`); a broken LLM degrades to inert. `AISelfHealHandler.heal` (`ai_self_heal.py:414`) runs a bounded ReAct loop over screenshot + `screen_snapshot` ref rows + the failed intent, with `HEAL_ACTION_SCHEMA` (`ai_self_heal.py:149`). The prompt names the target by its locator and, when known, by its suite element name: every `${name}` resolution site calls `step_params.name_locators`, and `_ai_self_heal` reads `test_context.element_names`. `closest_rows` ranks the screen rows against both, and the failed keyword, run again on a row that the locator itself names (`names_target`), completes the heal whatever the model's `completed` says (`complete_on_target`; a keyword that types a value completes only with that value). The handler names no keyword. `ActionKeyword` gives it the allowlist (`_heal_catalog`) and the prompt notes for those keywords (`HEAL_GUIDE`), and `agent_core.TYPED_VALUE_PARAMS` and `NON_VERIFYING_KEYWORDS` tell it which keywords type a value and which only move the screen. Self-heal does not use `AgentSession`. It shares the mechanism with NL mode: screen rows and ladders (`screen_snapshot`), the keyword tables, `signature_line` and `keyword_line` (`agent_core`), and `curation_prompt` with `curate_steps` (`step_curation`). A ref target becomes its `ladder` in `_bind_target` (`ai_self_heal.py:479`), so the recorded step keeps a stable locator, and params are logged in the form the CSV runner binds (a param past the hidden AOI params replays as `index=<n>`). Keyword actions run through `ActionKeyword._heal_execute` (`action_keyword.py:426`) on the allowlist in `_heal_dispatch` (`:309`) — `press_element`, `enter_text`, `scroll`, `swipe_by_percentage`, `press_keycode`, `press_by_percentage` — so healing uses the same locate ladder, with self-heal disabled during each call to avoid recursion. A popup stop (`E0206`, `E0407`, `E0408`) raised inside one ends the heal and fails the step as it is. A recovered step joins `_recent_steps` (`:306`) for `/save`. In a batch run `pop_heal` (`test_runnner.py:188`) reads and clears the heal record around every keyword, so a heal inside `Run Loop` or `Condition` counts for that keyword. A healed keyword's PASS event carries `healed`, `heal_summary` and `heal_steps` in `extra` (`heal_extra`, shared with `KeywordExecutor`): the replacement steps as JSON, masked, with each value of the keyword's `${name}` params written back as `${name}`. `JUnitEventHandler` writes them on its `<kw>` as `healed="true"` and a `<heal summary>` with one `<step keyword>` per step (`<arg>` children). Self-heal curates its steps through the same `curation_prompt` and `curate_steps` as NL mode (`step_curation.py`). Each loop keeps its own policy: the prompt, the reply schema, how an action runs and when the goal is reached. Two rules are still written in both loops, so change them together: a row that shares its text with another row is refused (`_shared_text_index` in `agent_core`, `_bind_target` in `ai_self_heal`), and the model does not see a secret typed value (`Focus`, `VALUE_PLACEHOLDER`).

## Keyword entry points (there are eight)

Adding a method to an API class is **not enough** if the keyword should be reachable everywhere.

1. **CSV/YAML runner** — `RunnerFactory.create_runner` (`execution.py:231`) calls `register(instance)` (`keyword_register.py:38`) on each API class, so new public methods are picked up automatically. Caller text `Title Case Words` is normalised via `func_name = "_".join(name.split()).lower()` (`test_runnner.py:463`).
2. **Python SDK / Robot Framework** — `optics.py:Optics` (`:147`) is a `@library(scope="GLOBAL")` class with an explicit `@keyword("Pretty Name")` method per keyword (e.g. `press_element` at `optics.py:648`) delegating to the API instances; `keyword` (`optics.py:57`) / `library` (`optics.py:68`) are no-op fallbacks without `robotframework`. **No auto-registration.** `@fallback_params` (`optics.py:102`) gives param-level fallback for `Union[str, List[str]]` params at the SDK boundary.
3. **HTTP server (`optics serve`)** — `helper/serve.py` mounts `common/expose_api.py`. `discover_keywords()` (`expose_api.py:497`) reflects over `KEYWORD_SOURCES` (`api/keywords.py:12`), the classes `build_keywords` registers, so another class an API module defines (`StepFailed`) adds no keywords (`_extract_keywords_from_class` (`expose_api.py:476`) skips `_*` and `test*` methods; `_humanize_keyword` (`expose_api.py:245`)). Types and docstrings flow into OpenAPI, so keep them accurate. The server is **unauthenticated**, so a caller is untrusted: `create_session` sets `Config.remote_caller` (only a stdio MCP server, via `expose_api.server_reads_allowed`, is local), `common/caller_policy.py` refuses what would make the server read its own files or environment (Read Data file/`ENV:` sources, `file:`/browser-internal URLs in launches and capabilities) and `Session.__init__` puts a remote session's outputs in its own temp folder, removed at terminate. `common/http_guard.py` adds the `OPTICS_CORS_ORIGINS` allowlist (none by default) and the Host check (DNS rebinding; loopback-bound servers, or any server once `OPTICS_ALLOWED_HOSTS` is set) to `optics serve`. The HTTP MCP server is a separate FastMCP app with no CORS allowlist: fastmcp's `host_origin_protection` checks its Host and Origin, with `OPTICS_ALLOWED_HOSTS` as `allowed_hosts`.
4. **Code generation (`optics generate`)** — `helper/generate.py` emits pytest or Robot code from the steps the runner reads: CSV through the runner's `CSVDataReader`, YAML steps through `parse_module_step` (`common/runner/data_reader.py:217`), which splits on the keyword catalogue (the public methods of `KEYWORD_SOURCES`). A step calls the `Optics` method named by its keyword in snake_case (`_method_name`, `generate.py:279`), and `name=value` params bind to that method's signature (`_sdk_parameters`, `generate.py:31`), so a keyword without an `optics.py:Optics` wrapper generates a call that fails at run time. `generate_test_file` merges config.yaml's `popup_rules` with each `popup_rules.json` into the generated `CONFIG` (`permissions` too). `PytestGenerator` (`generate.py:346`) and `RobotGenerator` (`generate.py:441`) render.
5. **`optics list`** — `main` (`helper/list_keyword.py:19`) prints `discover_keywords()`, the list `GET /v1/keywords` returns; `optics list <keyword>` prints its params in CSV column order (`param_1`, ...) and its docstring. `Optics`-only keywords don't show.
6. **Robot `Library    optics_framework.optics.Optics`** — only `@keyword` methods on `Optics` (same source as 2).
7. **`optics live`** — `LiveController._build_registry` (`helper/live.py:453`) uses `build_keywords`, like the runner, so new API methods work in the REPL/TUI and NL mode with no extra wiring.
8. **MCP server (`optics mcp`)** — the `core` toolset reaches every agent-visible keyword through `run_keyword` (`agent_core.keyword_catalog`); `--toolset full` registers each public API method as a string-typed tool. Both dispatch through `expose_api.execute_keyword`. A dedicated core verb needs a case in `agent_core.prepare` and a tool in `build_server`.

### Checklist when adding a keyword to `ActionKeyword`

- Add `def <name>(...)` on `ActionKeyword` (`api/action_keyword.py:262`).
- If it locates an element, return `self._locate_and_act(element, "<name>", act, intent_args, index=index, aoi=(...))` (`action_keyword.py:490`; see `press_element` at `:752`) to get strategies, AOI, retries and self-heal. To make it available to self-heal, add it to `ActionKeyword._heal_dispatch` (`:309`) and say how the model uses it in `HEAL_GUIDE` (`api/action_keyword.py:211`).
- Add an `optics.py:Optics` wrapper with `@keyword("Pretty Name")` (and `@fallback_params` for element args). `optics generate` calls it.
- Run `optics list` to confirm reflection picks it up.

## Layer order

`scripts/check_layers.py` (a pre-commit hook) holds the layers, lowest first, and refuses an import from a module to a module in a later layer. An import inside a function counts: it hides an import cycle from Python, but the two layers still depend on each other.

Run context → kernel → `utils` → project model → event contract → report → drivers → locator pipeline → agent kernel → session assembly → recovery → keyword API → project reader → execution engine → front ends.

- **Run context** is `common/test_context.py`. The runner writes its context variables and the lower layers read them, so it imports nothing from the package.
- **Event contract** is `common/events.py`: the `Event` model and `EntityType`. The runner sends events and the report reads them. The report learns an event's type from this module and never imports the runner.
- **Project model** holds `runner/step_params.py`, which binds a step's params to a keyword. **Project reader** is `runner/data_reader.py`: the YAML step parser needs the keyword catalogue, so the reader comes after the keyword API, and no layer before it can import it.
- When a lower layer needs a higher one at run time, the higher layer gives it a callable: `logging_config.on_shutdown` (the JUnit registry adds `close_all`), `PopupIO`, `KeywordExecutor`.
- Give a new module a layer in `LAYERS`. When the check fails, move the code to the layer that owns it; do not move the module's name to a later layer to make the check pass.

## Key data structures

- **Execution graph** — `TestCaseNode` (`models.py:83`) → `ModuleNode` (`:48`) → `KeywordNode` (`:38`), each with `state: State` (`:9`) mirroring `EventStatus` (`events.py:14`). Traverse with `current = head; while current: ...; current = current.next`.
- **`ElementData.elements: Dict[str, List[str]]`** (`models.py:154`) — name → ordered fallback list. `get_element(name)` returns the list (execute), `get_first(name)` the first value (dry-run / `resolve_param`).
- **`OpticsError` codes** (`error.py:283`; severities `E` / `W` / `X`):
  - `E0105` keyword not supported on this device platform → fatal, **not** in the `E02*` family.
  - `E0106` driver session gone. Raised by `raise_if_session_dead` (`common/session_liveness.py`) from broad `except` blocks in `strategies.py` that would otherwise report `E0201`/`E0202`/`E0303`/`E0403`; each driver defines what counts via `DriverInterface.is_dead_session_error`, and Appium/Selenium also count a refused connection on a `/session/` URL (`is_webdriver_server_unreachable` (`common/session_liveness.py:15`), so a remote OCR/image service that is down stays a strategy miss). Also raised when `Appium.web_context` can't switch back to `NATIVE_APP`. Reported as `ERROR`, not `FAIL`. Fatal, **not** in the `E02*` family.
  - `E0201` element not found in one source → drives fallback **levels 1 and 2**; `X0201` not found after all fallbacks → also keeps the ladder going.
  - `E0205` invalid element type. `E0303` screenshot empty/black (`ScreenshotStrategy.capture`, `strategies.py:716`). `E0402` keyword not in `keyword_map`.
  - `E0305` the camera does not see the device screen (moved, out of view or off), raised by `camera_screenshot`. `StrategyManager` and `_act_until_success` raise it as is instead of `E0201`, so no fallback level retries it and an assertion stops at once.
  - `E0405` the action ran but the screen doesn't show its result → re-raised at once, so no other strategy, self-heal or fallback acts again.
  - `E0501` config / required files missing. `E0701` execution failed. `E0702` test case / session missing. `E0706` the run stopped (Ctrl-C/SIGTERM) before the test case finished; `JUnitEventHandler._end_with_error` puts it on the `<error>` and the running `<kw>`. `E0801` uncategorised error.
- **Error messages** — each layer's `message` names only what that layer adds; `OpticsError.summary` (`error.py:322`) joins it with its cause's summary and drops a repeat, and `__str__` puts the code once in front. Never put `{e}` or `str(e)` of a cause into a message: pass `cause=` (or `plain(e)` (`error.py:229`) for a non-Optics exception, which keeps the readable first line). `explain` (`error.py:255`) gives the summary, a hint (the error's own `hint=`, else the innermost code's `ErrorSpec.hint`) and the code, which the tree's Failures panel, the plain/jsonl lines (`… [E0201]`), JUnit and the API payload (`hint`) show. A miss raises `ElementNotFound` (`error.py:445`, code `E0201`), which names the project's element (`element_label`, `error.py:433`) and lists the locators tried; `ElementNotFound.merge` (`error.py:484`) makes one sentence from the misses of fallback level 1. A step that fails inside a nested module, `Condition` or `Run Loop` raises `StepFailed` (`api/flow_control.py:120`), whose message is the path to it ("Inner › Press Element: …"). Wrong params raise `E0403` through `bind_params` (`common/runner/step_params.py:23`), which `FlowControl` shares for module steps.
- **`Event`** (`events.py:44`) — `entity_type` is an `EntityType` (`events.py:25`) value: `execution`, `test_case`, `module`, `keyword`, `session` or `popup`. The runner and every subscriber use the enum, so add a new type there. The field stays a `str`, so an event with another type is still accepted. Also ids, `status`, `args`, timings, `logs` (via `LogCaptureBuffer`, `Junit_eventhandler.py:106`).
- **`LocateResult`** (`strategies.py:586`) — `(value, strategy, annotated_frame, is_coordinates)`; `value` is an `(x, y)` tuple (vision) or a backend element handle.

## Tests

`scripts/check_tests.py` (a pre-commit hook) refuses tests that assert nothing, sleep for a fixed time outside a polling loop, read source code or assert a tautology (`hasattr`, `callable`, a constant, a value against itself). The `ruff-tests` hook adds a broad `pytest.raises`, an assert inside `except` and commented-out code.

A test earns its place only when all three are true:
1. It guards behavior that a user, a caller or a protocol can see, and a credible regression makes it fail.
2. No other test guards that behavior. Each contract has one owner, at the strongest boundary that is cheap to drive: `run_project`, the `Optics` facade, `optics serve`, an MCP session, a driver against a real browser, a CLI command.
3. It calls the code as its user does. Do not test a `_private` helper that a public path already covers.

Do not write:
- a test whose expected value repeats the code's logic, or one that checks that a method, attribute, constant or file exists;
- a test that asserts removed code stays gone;
- a test that mocks the unit under test, then asserts what the mock returns;
- one test per input. Add a row to the table (`pytest.mark.parametrize`) of the test that owns the behavior.

Prefer journeys. One test that runs a project through `run_project`, or one MCP session, and checks several outcomes replaces many tests of helpers (`tests/units/common/test_runtime_variables_e2e.py`, `tests/integration/test_playwright_journey.py`).

When a change breaks a test, either the test found a regression (fix the code) or the test was coupled to the implementation (rewrite it against behavior, or delete it). Never edit a test only to make it agree with new code.

## Hard rules

1. **Run pre-commit before committing** (`poetry run pre-commit run --files <changed>` or the git hook; never `--no-verify`). It chains ruff, bandit, whitespace/YAML/JSON checks, commitizen, gitleaks, `scripts/check_layers.py` (see "Layer order") and `scripts/sonar_lint.py`, which runs the SonarCloud rules this project keeps hitting offline, on the changed lines only (`--all` for every line, `SONAR_LINT_BASE` for another base). Suppress a finding with `# NOSONAR`, which SonarCloud also honours.
2. **Trace the blast radius before changing a function** (`grep -rn "<name>" optics_framework/ tests/`):
   - Renaming a public method on `ActionKeyword` / `AppManagement` / `Verifier` / `FlowControl` breaks every CSV/YAML that names it, its `optics.py:Optics` wrapper and the code `optics generate` emits.
   - A keyword's Robot display name (the `@keyword(...)` string) is independent of the method name.
   - The `E02*` / `X0201` check in `fallback.advances` (`is_element_not_found`) (`common/fallback.py:18`) is load-bearing; don't reuse the prefix for non-element errors.
   - The `EntityType` (`events.py:25`) values drive `EventStreamPrinter` and `JUnitEventHandler._handle_test_case_event` (`Junit_eventhandler.py:258`) / `_handle_module_event` (`:296`) / `_handle_keyword_event` (`:306`).
   - Changing how `determine_element_type` (`utils.py:317`) classifies a string changes which strategy fires.
3. **Conventional Commits** — the commitizen hook (`.cz.toml`) rejects anything but `feat:` / `fix:` / `refactor:` / `docs:` / `chore:` / `test:` / `perf:` / `style:` / `build:` / `ci:`.
4. **Python 3.12+ only** (`python = ">=3.12,<4.0"`); use modern typing.
5. **Do not edit generated trees** (`__pycache__/`, `dist/`, `.tox/`, `htmlcov/`, `execution_output/`).

## Pitfalls

- **One parser per input kind.** `${name}` references are scanned only by `utils.var_refs` / `utils.substitute_vars` (one linear pass); data expressions (Evaluate, Condition, JSONPath conditions, Read Data filters) run only through `common/expression.py`, which never calls `eval` and caps size and cost (`E0406`); project YAML is parsed only by `config_handler.load_project_yaml` / `parse_yaml`, which refuses alias bombs. Don't add a regex, `eval` or `yaml.safe_load` beside them.
- **Four `${name}` resolution sites.** `TestRunner.resolve_param` (`test_runnner.py:328`) returns the *first* value and `_build_param_candidates` (`:566`, through `step_candidates`) the *list* — dry-run vs execute divergence usually traces here. `FlowControl._resolve_param` (`api/flow_control.py:161`) and `Verifier._resolve_param` (`api/verifier.py:216`) use `step_params.resolve_scalar_param` (`common/runner/step_params.py:129`) for the params those keywords read themselves (a `Run Loop` count, a `Condition` value); it resolves only a param that is exactly one `${name}` and raises `E0201` for a missing variable. `utils.substitute_inline` (`common/utils.py:122`) replaces `${name}` inside a longer param with the first value (`E0403` if unknown; a whole-param `${name}` is left to the runner forms; `$${name}` escapes); keywords marked `@substitutes_own_vars` (`Condition`, `Evaluate`, `Read Data`) are skipped.
- **Four fallback layers.** "Element not found after retries" usually means level 2 exhausts before level 1 retries — check `execution_tracer` logs. With `ai_self_heal` on, a level-4 recovery can mask a terminal `E0201`/`X0201`; look for the "AI self-heal" log lines.
- **`KeywordRegistry.register` is greedy.** Every public callable becomes a keyword and may collide across API classes (only a warning at `keyword_register.py:53`). Prefix helpers with `_`.
- **`act` must handle both locate shapes** (`(x, y)` tuple or element handle). Any exception in `act` counts as that strategy failing, so a bug in `act` looks like element-not-found.
- **`optics.py:Optics` ≠ the runner's keyword set.** The runner, HTTP API and `optics list` reflect the API classes; the SDK uses explicit `Optics` methods. They can drift.
- **Async re-entrancy.** `ExecutionEngine.execute` must run inside `asyncio.run(...)` via `BaseRunner.run`. `PytestRunner` (`test_runnner.py:1113`) uses `queue_event_sync` (`:134`), which runs each subscriber in its own `asyncio.run`, on a worker thread when `pytest.main` runs inside the batch's loop; don't mix the two paths.
- **`Session` mutates the passed-in `Config`** (`json_path`, `execution_output_path`); don't share a `Config` across sessions.
- **Truncated JUnit XML on long runs** → raise `OPTICS_EVENT_DRAIN_TIMEOUT_S` (default `2.0`) before debugging logic.
- **Robot Framework is optional.** Don't hard-import `robot.api`; mirror the try/except in `optics.py`.
- **Stubbed source methods hide strategies.** `LocatorStrategy._is_method_implemented` (`strategies.py:131`) excludes a source whose method only raises `NotImplementedError`, so a badly stubbed source silently drops out.
- **Two test trees.** `tests/units/` and `tests/integration/` run under one `pytest` (`testpaths = ["tests"]`). Markers: `white_box`, `black_box`, `hybrid`, `generate`.
