## Execute journey (CLI → driver action)

The chain behind `optics execute <folder>`:

1. `optics_framework/helper/cli.py:571` — `main()` dispatches via `ExecuteCommand.execute` (`cli.py:491`) → `execute_main(folder_path, runner, use_printer, include, exclude)` in `optics_framework/helper/execute.py:892`. `cli.py`'s helper imports sit in a `try/except ImportError` (`cli.py:20`) that shows the failure through `abort_with_panel` / `reinstall_guidance` (`helper/abort.py`); the package root resolves the `Optics` re-export lazily (PEP 562) so importing `helper.cli` doesn't load the vision stack before that guard runs.
2. `execute_main` delegates to `run_project` (`execute.py:968`), which builds `ExecuteRunner(args)` (`execute.py:938`, subclass of `BaseRunner` at `execute.py:670`) and calls `asyncio.run(...)`. In-process callers (`quickstart`) use `run_project` to get a pass/fail value instead of `execute_main`'s `sys.exit(1)`.
3. `BaseRunner.__init__` (`execute.py:680`) discovers and loads synchronously:
   - `find_files(folder_path)` (`execute.py:83`) sorts paths into `test_case` / `module` / `element` / `api` / `error_definitions` by CSV header or YAML keys, via `identify_file_content` (`execute.py:236`) and `_categorize_file_by_content` (`execute.py:166`). A YAML with both `driver_sources` and `element[s]_sources` is the project config (`_is_config_file`, `execute.py:153`); `resolve_config_file` (`common/config_handler.py:28`) expands `$NAME` / `${NAME}` / `${NAME:-default}` and makes `./`/`../` values absolute, raising `E0501` for an unset variable or a missing file (output paths are exempt). It runs only where a config *file* is read (execute/dry_run, `live._config_from_yaml`, `doctor._load_project_yaml`), never in `Config`: `optics serve`/`optics mcp` build `Config` from request bodies, and resolving there would let a remote caller read the server's environment and probe its files. `optics configure --edit` reads without resolving, so saving keeps the references.
   - `_load_test_cases` (`execute.py:729`) / `_load_modules` (`:738`) / `_load_elements` (`:760`) / `_load_api_data` (`:789`) read files via `CSVDataReader` (`common/runner/data_reader.py:322`) / `YAMLDataReader` (`:458`) into `ModuleData` (`common/models.py:148`) / `ElementData` (`:164`) / `ApiData` (`:291`). `_load_error_definitions` (`execute.py:795`) reads `error_definitions.csv` via `read_error_definitions` (`data_reader.py:437`) into `ErrorDefinitions` (`models.py:320`).
   - `_load_templates` → `discover_templates` (`execute.py:60`) collects images into `TemplateData` (`models.py:305`).
   - `_filter_and_build_execution_queue` → `filter_test_cases` (`execute.py:296`, see "Test case selection") + `build_linked_list` (`execute.py:444`), which threads `TestCaseNode → ModuleNode → KeywordNode` (`models.py:77` / `:42` / `:36`); per-test setup/teardown get their own `Setup (<test>)` / `Teardown (<test>)` nodes. Each node has a `CaseKind` (`models.py:18`): only a name ending with "Suite Setup", "Suite Teardown", "Setup" or "Teardown" wraps the tests (`case_kind`, `execute.py:321`), and a second one of a kind stops the run with `E0503`.
   - `_setup_session` → `SessionManager.create_session` (`common/session_manager.py:152`) builds a `Session` (`session_manager.py:101`) with `EventSDK` and `OpticsBuilder` (`common/optics_builder.py:31`), keeping only enabled configs (`_get_enabled_config_list`, `session_manager.py:29`). `Session.__init__` adds drivers, element sources and detectors, then calls `self.optics.get_driver()` to fail fast — `OpticsBuilder.instantiate_driver` (`optics_builder.py:115`) / `instantiate_element_source` (`:126`) raise `E0501` when nothing is configured. With no driver enabled, `session.driver` is `None`, and the run stops only if a reached module calls an `ActionKeyword`/`AppManagement`/`Verifier` keyword (`BaseRunner._needs_driver`).
4. `BaseRunner.run("batch")` (`execute.py:903`) awaits `ExecutionEngine.execute` (`common/execution.py:395`).
5. `ExecutionEngine.execute`:
   - Starts the session's `EventManager` from `get_event_manager(session_id)` (`common/events.py:206`, registry at `:174`).
   - `RunnerFactory.create_runner` (`execution.py:242`) builds `KeywordRegistry` (`common/runner/keyword_register.py:5`) and, via `session.optics.build(cls)` (`optics_builder.py:192`), `ActionKeyword` (`api/action_keyword.py:191`), `AppManagement` (`api/app_management.py:7`) and `Verifier` (`api/verifier.py:13`) when `session.driver` is set, plus `FlowControl` (`api/flow_control.py:58`) always. `KeywordRegistry.register` (`keyword_register.py:22`) maps every non-underscore callable into `keyword_map`. Then it picks `TestRunner` (`runner/test_runnner.py:173`), `PytestRunner` (`:1137`) or `KeywordRunner` (`:1558`) by `runner_type`.
   - `BatchExecutor.execute` (`execution.py:50`) → `TestRunner.run_all` (`test_runnner.py:1095`).
6. `TestRunner.run_all` → `_process_test_case` (`:860`) → `_process_module` (`:777`) → `_execute_keyword` (`:435`):
   - Looks up `func_name = "_".join(name.split()).lower()` (`:466`) in `keyword_map`.
   - `_build_param_candidates` (`:513`) expands every `${var}` to `ElementData.get_element(var)` — the **fallback list** — and other params to one-element lists.
   - `_try_execute_with_fallback` (`:549`) tries `itertools.product(*param_candidates)` (at most `MAX_ATTEMPTS = 20`). It advances **only** when the `OpticsError.code` starts with `E02` (element not found) or equals `Code.X0201` (`:580`); anything else is fatal via `_handle_keyword_exception` (`:595`). This is **fallback level 1** (param-axis).
7. Every locate-based `ActionKeyword` action (`press_element`, `swipe_from_element`, `scroll_from_element`, `enter_text`, `enter_number`, `clear_element_text`, `get_text`, and through `press_element` the checkbox/radio/dropdown keywords; **not** `detect_and_press`/`*_until_element_appears`, which call `Verifier` directly) builds an `act(located)` callback and passes it to `ActionKeyword._locate_and_act` (`api/action_keyword.py:410`):
   - takes a screenshot via `_capture_screenshot_safe()` → `StrategyManager.capture_screenshot` (`common/strategies.py:952`);
   - `_parse_aoi_param` (`:37`) normalises the `aoi` tuple; `_locate_element` (`:53`) calls the `strategy_manager.locate(...)` **generator** (`strategies.py:672`);
   - `_act_until_success` (`:442`) pulls one result at a time, saves an annotated screenshot and calls `act(result.value)`, so a later strategy locates only after the earlier act fails. If every result fails **and** AI self-heal can't recover, it raises `OpticsError(Code.X0201, ...)`; if nothing was yielded, the strategy layer's `Code.E0201` propagates.
8. `StrategyManager.locate` (`strategies.py:758`) is **fallback level 2** (self-healing location):
   - `utils.parse_text_only_prefix(element)` (`common/utils.py:362`) strips the `TEXT_ONLY:` prefix that forces vision search.
   - `utils.determine_element_type(element)` (`utils.py:290`): image extension → `"Image"`; `text=` / `TEXT_ONLY:` → `"Text"`; `css=` → `"CSS"`; `xpath=`, `/`, `//`, `(` → `"XPath"`; else `"Text"`.
   - Iterates `self.locator_strategies` from `StrategyFactory` (`strategies.py:558`) and its priority registry (`:562`): `XPathStrategy` (`:134`) and `TextElementStrategy` (`:161`) call `element_source.locate`; `TextDetectionStrategy` (`:188`) runs OCR and `ImageDetectionStrategy` (`:290`) template matching or remote OIR on a screenshot.
   - Each strategy's static `supports(element_type, element_source)` (`:61`) gates it; `LocatorStrategy._is_method_implemented` (`:71`) skips stubs that only `raise NotImplementedError`.
   - `_try_strategy_locate` (`:714`) calls `locate(...)` (or `locate_with_aoi(...)` for a non-default AOI) and logs the attempt to `execution_tracer`. Results are yielded as `LocateResult(value, strategy, annotated_frame)` (`:596`); with none, it raises `OpticsError(Code.E0201, ...)` (`:785`).
9. The `act` callback (e.g. in `press_element`, `action_keyword.py:528`) presses a `(x, y)` tuple with `driver.press_coordinates`, else `driver.press_element(located_node, ...)`. `self.driver` is an `InstanceFallback[DriverInterface]` (`common/base_factory.py:217`) — **fallback level 3** (driver-axis); call sites try each enabled driver in `config.yaml` order. `_act_until_success` runs `act` inside `InstanceFallback.routed_to(owner)` (`base_factory.py:234`), so a result is only acted on by the driver that found it (a Playwright locator handed to Appium would "succeed" silently: its `click()` returns an un-awaited coroutine).
10. `TestRunner._send_event` (`test_runnner.py:368`) publishes `Event`s (`events.py:33`) to the session's `EventManager`; `JUnitEventHandler` (`common/Junit_eventhandler.py:167`) builds the XML and `TreeResultPrinter` (`common/runner/printers.py`) the live display.
11. Before the suite teardown (a teardown often closes the app), or after the last test case, `TestRunner.run_all` (`test_runnner.py:1095`) calls `_capture_end_of_run_artifacts` (`:686`, see on-screen error detection). A failed suite setup skips every case but the suite teardown, and a failed test setup skips its test (`SetupGuard`, `test_runnner.py:152`, shared with `PytestRunner`, which skips with `pytest.skip`); a skipped case is a `NOT_RUN` test_case event, reported as `<skipped>` with the reason. `_note_failure` (`test_runnner.py:209`) keeps each failure's code on `Event.code`, which the report writes as `code` on `<failure>`, `<error>` and a failed `<kw>`; every `<testcase>` carries its `kind`. `_start_run` gives `JUnitEventHandler.plan_run` (`Junit_eventhandler.py:187`) every planned step, so steps and test cases that never ran are reported as `NOT_RUN`; a failed test case also gets screen + page source via `_capture_failure_artifacts` (`:708`). `BaseRunner.cleanup` (`execute.py:930`) → `SessionManager.terminate_session` (`session_manager.py:168`) ends the driver and removes temp files and the `EventManager`; `ExecutionEngine._drain_events_and_shutdown` (`execution.py:377`) waits up to `OPTICS_EVENT_DRAIN_TIMEOUT_S` (default `2.0s`). `_run_until_stopped` (`execute.py:997`) turns SIGINT into `KeyboardInterrupt` and SIGTERM into `SystemExit(143)` inside the running keyword so cleanup still runs (`PytestRunner` ends pytest there and raises the stop again after `pytest.main`), and `JUnitEventHandler._end_with_error` (`Junit_eventhandler.py:406`) marks the running test case `<error>`. A `StartProblem` from `_preflight` (`execute.py:555`) is passed to `plan_run` as `start_error` before `abort_with_panel`, so queued test cases are reported as `ERROR`. The suite name and every `classname` are the project folder's name (`session_<id>` only without a project).

`dry_run` follows the same path with `DryRunExecutor` (`execution.py:93`) and `_process_test_case(..., dry_run=True)`: it resolves params via `resolve_param` (`test_runnner.py:294`, the *first* value, not the list) and checks `keyword_map` membership without calling methods — a known dry-run vs execute divergence. Dry-run is a **validator**: an unknown keyword or unresolved `${var}` becomes a per-keyword `FAIL`, not an exception (`_dry_run_module`, `test_runnner.py:994`).

## Test case selection (`include` / `exclude`)

`--include` / `--exclude` (`_add_selection_arguments`, `cli.py:375`; `nargs="+"` + `action="extend"`) reach `BaseRunner.__init__`, which, when **either** is given, replaces **both** `config.include` and `config.exclude` (never merged). Python callers pass the same keyword args to `run_project`/`execute_main`/`dryrun_main`, where `None` means "use config.yaml".

Matching lives in `helper/case_selection.py` (`select_test_cases`, `:46`). `filter_test_cases` (`execute.py:296`) selects only regular cases; setup/teardown are always kept.
- Names compare after `" ".join(name.split()).casefold()`. `*` and `?` are the only wildcards; every other character, `[` and `.` included, is literal (not fnmatch).
- Include narrows first, then exclude removes.
- **Strict validation.** Every pattern must match a selectable case, else `OpticsError(E0702)` lists the bad patterns with "Did you mean" suggestions (a pattern that only hits setup/teardown is called out). An empty selection also raises `E0702`; a blank name raises `E0503`. The same rules apply to config.yaml, because a typo there used to silently run only the fixtures. `BaseRunner._exit_invalid_selection` shows the error (exit 3) before any session exists.

## On-screen error-detection journey

An auto-discovered `error_definitions.csv` (`error_code,match_string,description,severity`) is read by `_load_error_definitions` (`execute.py:795`) into `ErrorDefinitions` (`common/models.py:320`) on the `Session`. Once per batch run, before the suite teardown, `TestRunner._capture_end_of_run_artifacts` (`test_runnner.py:686`) saves a screenshot + page source (`_save_end_of_run_pagesource`, `:713`) and runs `_run_end_of_run_detection` (`:746`) with `extract_visible_text` (`common/error_detection.py:35`) and `detect_errors_in_text` (`:81`, case-insensitive **substring**, not regex). Matches become a synthetic failing JUnit testcase (`JUnitEventHandler.add_detected_errors`, `Junit_eventhandler.py:322`) and a failed `on-screen-error-detection` result, so the run exits `1`.

This is automatic. Library/Robot users get on-demand equivalents, `Add Error Definitions` (`optics.py:520`) and `Capture And Detect Errors` (`optics.py:562`), which exist **only** on the `Optics` facade, so the CSV/YAML runner, `optics serve`, `optics mcp` and `optics list` don't see them.

## Live session journey (`optics live`)

`optics live` runs keywords against a running target without a test folder. It is a **separate path from execute** (no `ExecutionEngine`, `EventManager` or JUnit) but reuses the keyword and element machinery.

1. `cli.py:514` `LiveCommand` → `live_main(folder_path)` (`helper/live.py:1562`); `LiveArgs` (`cli.py:509`) is the args model.
2. `_compose_config` (`live.py:256`) builds a `Config` from the project folder (`_config_from_yaml` / `_load_partial_config`, `:230`/`:228`). Whichever single driver is enabled wins (`_enabled_drivers`, `:244`); no driver is hard-coded.
3. `LiveController.__init__` (`live.py:301`) creates a `Session` via `SessionManager`, and `_build_registry` (`:433`) builds a `KeywordRegistry` exactly like `RunnerFactory.create_runner`. Live executes through the API layer, so it gets self-healing, AOI and screenshots for free.
4. `run_keyword` (`live.py:532`). Live **reimplements the param-fallback ladder (level 1)** in `_attempt_combos` / `_build_candidates` / `_resolve_candidate` (`:650`/`:741`/`:758`), mirroring `TestRunner._try_execute_with_fallback` / `_build_param_candidates`; the two must be kept in sync. `_run_single_combo` runs under `keyword_outcome.capture()`, so an error the keyword logs without raising fails it as `E0401`.
5. **Natural-language mode** — `NaturalLanguageAgent` (`common/nl_agent.py:243`) is a bounded loop (`max_steps`, default 15) over one `agent_core.AgentSession` per run (`run`, `nl_agent.py:259`; each session call runs in its own `asyncio.run`, so `run` raises inside a running loop). Each turn (`_turn`, `nl_agent.py:297`) observes the screen as `e<N>` ref rows, asks the LLM for one reply against `ACTION_SCHEMA` (`nl_agent.py:92`), and sends at most one correction (`_correction`, `nl_agent.py:409`). `AgentSession.act` runs, settles, judges and records each action. Guards on `session.steps` end runs that act blindly or stop changing the screen. The screenshot goes to the LLM only when `_wants_image` (`nl_agent.py:359`) asks for it, and a hard turn goes to the `escalation_model`. A failed screen read falls back to the page source (no refs; a `done` then ends as `done_unverified`), and an `E0106` ends the run as a lost session. `done` is gated by `AgentSession.check` (`_done`, `nl_agent.py:435`); a `done` without expectations ends as `done_unverified`. Wired in `LiveController._get_nl_agent` (`live.py:1259`), whose `_agent_call` (`live.py:689`) goes through `_attempt_combos`, so level-1 fallback still applies; driven by `run_natural_language` (`:1334`). Recording is commit-on-done: `_commit` (`live.py:1385`) keeps the run's steps and elements only for `done` / `done_unverified`, and `_elements_to_save` (`live.py:1402`) writes secret values as `<redacted>`. With `curate_on_done`, `_curate` (`nl_agent.py:595`) runs `curate_steps` (`step_curation.py:57`) to keep a minimal replayable subset; any abnormal outcome keeps every step, so curation never destroys a working recording. The LLM comes from `session.optics.get_llm()` (`gemini` / `openai` / `anthropic`, each a same-named extra; `optics-framework[llm]` installs all). Screenshot bytes for self-heal and NL mode come from `StrategyManager.capture_screenshot_bytes` (`strategies.py:968`), which prefers each source's native encoded screenshot.
6. The TUI is `helper/live_tui.py`. `/save` (`live.py:802`, `save(test_case, module_name, *, allow_append=False)`) **appends** to `modules/modules.csv`, `test_cases/test_cases.csv` and `elements/elements.csv`, one module per `/save`. A name collision raises `SaveConflictError` (`:163`) unless `allow_append=True`. User docs: `docs/usage/live_usage.md`.

Device features are Appium only, for Android and iOS: `list_devices` (`live.py:1145`) shells out to `adb` and `idevice_id` and `switch_device` (`:1157`) rebuilds the session with the chosen `udid`, gated by `supports_device_switching` (`:1079`). The `adb` hot-plug monitor is Android only (`supports_adb_hotplug`). If device hot-swap should generalise, it belongs behind `DriverInterface`, not in `helper/live.py`.

## MCP server journey (`optics mcp`)

`optics mcp` exposes the keywords over MCP. It is a **thin in-process wrapper over `common/expose_api.py`**: it does only transport and rendering, never its own session or execution logic. The agent logic lives in three core modules that the NL agent shares:
- `common/agent_core.py`: `AgentSession` (`agent_core.py:661`), built from async `read(png)` and `run(keyword, params)`, with the `RefTable`, the steps and a `Recorder` (`agent_core.py:541`). `AgentSession.act` (`agent_core.py:780`): `prepare` (`agent_core.py:489`; resolves the target and builds keyword calls, raising `Fail` for `stale_ref`, `unknown_ref`, `ambiguous`, `invalid_params` or `no_locator`) → loop guard → calls (`session_lost` raises at once) → settle (after a non-typing success, at most 2 extra reads 0.6 s apart until two reads agree; a screen with no rows is re-read while loading; read-only keywords read once, `_waits_for_change`) → `screen_snapshot.verify`, polled for up to `EXPECT_WAIT_S` while an expectation is unmet → `Recorder.add`.
- `common/screen_snapshot.py`: `Row`, `RefTable` (`screen_snapshot.py:294`), `diff`, `verify` (`screen_snapshot.py:385`), `ladder` (`screen_snapshot.py:471`; `act` acts now, `save` is recorded, `replay` is what a replay uses) and `is_secret` (`screen_snapshot.py:489`). `RefTable.snapshot` keys each row statelessly by `_identity` (a unique positionless locator plus nearby context, else bounds/class/label) and keeps a session-long key-to-ref map, so a ref survives overlays, filters and relabels and returns on an earlier screen.
- `common/keyword_outcome.py`: collects one keyword run's outcome in a ContextVar (`capture`, `keyword_outcome.py:70`): the winning strategy and the first ERROR logged on `optics.internal` without a raise (`asyncio.to_thread` carries the ContextVar along).

1. `cli.py:MCPCommand` → `run_mcp_server(transport, host, port, toolset)` (`helper/mcp_server.py:926`); `MCPArgs` (`cli.py:182`): `--transport {stdio,http}` (default stdio), `--toolset {core,full}` (default `OPTICS_MCP_TOOLSET`, else `core`).
2. `build_server(toolset)` (`mcp_server.py:774`) builds a `fastmcp.FastMCP` with `SERVER_INSTRUCTIONS` (`mcp_server.py:104`, under 1,800 characters). Every tool carries all four MCP annotations (`_annotations`, `mcp_server.py:196`), and each core tool has a lean input schema and one of four literal output schemas; a test keeps the core `tools/list` under 10,000 characters.
   - **Core (default)** — `start_session`, `terminate_session`, `observe`, `tap`, `type_text`, `scroll`, `press_key`, `launch_app`, `check`, `run_keyword`. Acting tools go through `_act` (`mcp_server.py:535`) → `_guarded` → `AgentSession.act`, and `_step_reply` (`mcp_server.py:502`) renders the `Step` as short text plus `structuredContent`. `run` is `_run` (`mcp_server.py:427`): `expose_api.execute_keyword` under `keyword_outcome.capture()` (a logged error without a raise becomes `E0401`, `silent_failure`). `verified` is `pass|fail|unknown`; an unreadable screen gives `unknown`, and an action whose target was not named exactly and was found by OCR or image is never `pass`. The loop guard refuses an action when the last three steps since the last `observe`/`check` had the same `attempt_key` (`agent_core.py:513`) and made no progress. `check` (`_check`, `mcp_server.py:552`) calls `AgentSession.check` (`agent_core.py:820`). `observe` (`_observe_screen`, `mcp_server.py:579`) issues refs. `run_keyword` reaches every keyword in `keyword_catalog` (`agent_core.py:239`; coordinate keywords only with `OPTICS_MCP_ALLOW_COORDINATE_TAPS=1`, see `_reachable` (`mcp_server.py:219`)), expands refs to live locators and clamps timeouts to 60 s.
   - **Full** — the older surface: one string-typed tool per public `ActionKeyword`/`AppManagement`/`Verifier` method (`_make_keyword_tool` (`mcp_server.py:596`), defaults via `_stringify_params` (`mcp_server.py:194`), `agent_core.RESOURCE_KEYWORDS` excluded), `screenshot`, and the non-clashing core tools (`scroll` and `launch_app` stay keyword tools).
   - **`start_session`** — without `elements_sources`, `_default_sources_for_driver` (`mcp_server.py:74`) fills the driver's sources (`ElementSourceFactory.available_sources`, ranked by `_SOURCE_RANK`); an explicit empty list is kept. With `app`, it also launches it.
   - **Resources** (each with an explicit `mime_type`) — `optics://keywords` (exactly what the `run_keyword` enum accepts; keep them in sync), `optics://project-format`, `optics://browser-profiles` (local Chrome/Edge profiles; only a stdio server lists them or accepts a caller's `capabilities.profile`, via `expose_api.host_profiles_allowed` and `_refuse_server_side_reads`; a caller's `user_data_dir` is always refused), `optics://session/{session_id}/{screenshot,source,elements,screen_elements}` and `optics://session/{session_id}/steps` (`_steps`, `mcp_server.py:588`): steps plus `modules_csv`/`elements_csv` from `Recorder.csv` (`agent_core.py:609`). The Recorder writes element params as `${name}` with `ladder(...).save` rungs and params as the CSV runner binds them (`agent_core.runner_params`). A typed value is secret when `is_secret` marks the target row or the field `agent_core.Focus` holds, judged on the screen before the typing; with no held field, or one that is not an input, any secret field on the screen counts (and a raw XPath/CSS locator that names no row counts when the screen has a secret field). Secret values are saved as a `<field> value` element written as `<redacted>`, and a secret input's label is never its element name. `optics live` shares the same `Focus`.
3. **Per-session state** — `_Slot` (`mcp_server.py:266`) holds the `AgentSession`, an `asyncio.Lock`, a `busy` flag and `last_used`. `_slot` (`mcp_server.py:360`) picks the only open session when `session_id` is empty (`_start` ends a session whose slot could not be built, so none keeps a browser), after `_sweep` (`mcp_server.py:339`) ends sessions idle past `OPTICS_MCP_SESSION_IDLE_S` (default 900, `0` off). `_guarded` (`mcp_server.py:379`) serialises calls, caps each at `OPTICS_MCP_CALL_TIMEOUT_S` (default 100) and keeps the session busy until a timed-out driver call ends. `_driver_read` (`mcp_server.py:415`) holds `keyword_lock` around screen reads.
4. **Errors are tool results**: `as_fail` (`agent_core.py:200`) maps exceptions to a `Fail` (`agent_core.py:107`) with a kind, the optics code, one fact line and a `Next:` line from `agent_core.ADVICE`. `E0101`/`E0103`/`E0106` end the session through `_end` (`mcp_server.py:325`); `E0102` does not. Only the full toolset still raises `ToolError`.
5. `fastmcp` is the optional `mcp` extra; imports are guarded (`_require_fastmcp`).

**Deliberately tool-light.** There are **no** recording, suite-CRUD, replay, device-discovery or `doctor` tools: an agent builds a suite from the `steps` resource and `optics://project-format` and runs it with `optics execute`. The MCP layer never shells out to `adb` or assumes a device type; the earlier `mcp_authoring.py`/`mcp_diagnostics.py` modules (~24 tools) were removed for this reason.

`optics mcp` and `optics serve` have separate `SessionManager`s, so sessions are **not shared**; stopping `optics mcp` (including SIGTERM) ends its sessions. User docs: `docs/usage/mcp_usage.md`.

## Mobile web journey (Appium: browsers and WebViews on Android and iOS)

Web pages on a device run through the **same Appium session** as native apps, with no browser driver and no context-switch keyword. The session stays in `NATIVE_APP`, so native locators and OCR keep working on web pages and an app that taps a link continues in the browser. User docs: `docs/usage/mobile_web.md`. End-to-end tests: `tests/integration/test_appium_app_to_browser.py` (emulator in `OPTICS_E2E_EMULATOR`; clears Messages and Chrome data) and `tests/integration/test_appium_ios_app_to_browser.py` (simulator in `OPTICS_E2E_SIMULATOR`).

1. **Web locators** (`css=…`, bare CSS, DOM XPath) reach `AppiumWeb` (`engines/elementsources/appium_web.py`). `AppiumWeb.locate` (`appium_web.py:99`) returns `None` for text, image and native XPath (`utils.is_native_xpath`, `common/utils.py:344`) and acts only while `Appium.native_ui_platform` (`appium.py:308`) is Android or iOS: an iOS `browserName`/`autoWebview` session already reads the page natively, and `web_context` would drop it to `NATIVE_APP`.
2. `Appium.web_context` (`engines/drivers/appium.py:1608`) enters the page and always switches back to `NATIVE_APP`. **iOS** (`_enter_ios_web_context`, `appium.py:1654`): tries `com.apple.SafariViewService` pages first, then pages of the app in front, and takes the first visible page that holds a locator (`_page_holds`); a page that times out goes into `_frozen_web_contexts` until its URL or title changes. `_IOS_CONTEXT_OPTIONS` (`appium_platforms.py:58`, native sessions only) lists every app's pages and bounds the waits (an ad-hoc app's inspector bundle id is `process-<Name>`). **Android**: the first entry goes through `_foreground_web_context` (`appium.py:1719`) and `_context_name` (`appium.py:108`; the switchable name is `webviewName`, not `webview`); `_focus_window` (`appium.py:1736`) picks the tab showing that URL from `Target.getTargets`, because `switch_to.window` brings a tab to the front. A `browserName` session names Chrome `CHROMIUM`, not `WEBVIEW_chrome`. Later entries use `_reenter_web_context` (`appium.py:1699`), since `mobile: getContexts` waits 2 s on every frozen app's DevTools socket; `_ANDROID_CONTEXT_OPTIONS` (`appium_platforms.py:50`) keeps context switches off those sockets.
3. The element is scrolled into view, must be `is_displayed()`, is uncovered by `AppiumWeb._uncover` (`appium_web.py:132`) and measured by `Appium.web_element_screen_rect` (`appium.py:1778`). `_web_transform` (`appium.py:1797`) maps CSS pixels to the screen by finding an injected invisible probe natively, so toolbars, zoom, the keyboard and several WebViews are all accounted for (scrolled-out elements are not in the accessibility tree, so the probe, not the element, is measured). `AppiumWeb._settled_rect` (`appium_web.py:142`) waits out toolbar animation. `locate` returns a `ScreenPoint` (`common/elementsource_interface.py:6`): an `(x, y)` tuple that also carries the text, `covered` and `enabled`/`checked` state that `Verifier.is_element` reads. A tap on a covered element is refused (`E0201`); only `Get Text` passes `allow_covered=True`.
4. `AppiumWeb.check_elements` (`appium_web.py:165`) is the assertion loop's one look; `assert_elements` (`appium_web.py:151`) wraps it. Sources declare lookups via `ElementSourceInterface.can_locate` (`common/elementsource_interface.py:81`), and strategies skip elements whose `can_assert` is false, so a `css=` assert never queries native sources and a text assert never enters the web context. Native sources decline DOM-only XPaths (`utils.is_dom_only_xpath`, `common/utils.py:352`).
5. **Screen elements.** `AppiumWeb` sets `SUPPLEMENTS_SCREEN_ELEMENTS` (`common/elementsource_interface.py:39`), so `StrategyManager.get_interactive_elements` (`strategies.py:1021`) merges the page into the native list via `merge_screen_elements` (`strategies.py:452`), dropping native entries a web entry mirrors and keeping containers (`_native_container`, `strategies.py:442`). `AppiumWeb.get_interactive_elements` (`appium_web.py:65`) uses the `WebDomInspector` (`engines/elementsources/playwright_page_source.py:244`) that Playwright shares, so both list the same nodes and locators. `_inspect_nodes` (`appium_web.py:73`) runs `BOUNDS_JS` (`playwright_page_source.py:42`) and `SUGGEST_LOCATORS_JS` (`playwright_page_source.py:83`) in one script; off-viewport nodes are listed with `offscreen: true`. Each row's `loc` is checked in the live DOM to match only that node and avoids generated ids and digits, so it is stable across runs.

`browserName`/`autoWebview` sessions start in the web context; `Appium._create_new_driver_session` (`appium.py:406`) moves Android ones to `NATIVE_APP`. `Appium.launch_app` (`appium.py:914`) opens a URL or deep link. The preflight only checks local `adb` devices when the server is local (`_is_local_server`, `helper/execute.py:601`).

## TV web app journey (Appium: Tizen and webOS)

A Tizen or webOS app is a web page with no native tree and no touch. Both profiles set `PlatformProfile.web_ui` (`engines/drivers/appium_platforms.py`), read by `Appium.is_web_ui` (`engines/drivers/appium.py:316`). User docs: "Smart TV (Appium)" in `docs/configuration.md`.

1. **Lookup.** `AppiumFindElement._query` (`engines/elementsources/appium_find_element.py:101`) accepts `css=` and turns a text locator into `utils.dom_text_xpath` (`common/utils.py:283`).
2. **Dispatch.** `press_element`, `enter_text_element`, `clear_text_element` and `get_text_element` carry `@_on_tv` (`engines/drivers/appium.py:175`) above `@supported_on(*MOBILE)`, which calls the same method on `TvWebApp` (`engines/drivers/appium_tv.py:263`, one per session via `Appium._tv_app` (`appium.py:324`)). Other phone methods raise `E0105`.
3. **Focus.** `TvWebApp.focus` (`appium_tv.py:309`) reads focus from the DOM after each key press; `_Route` (`appium_tv.py:224`) picks keys toward the target. `press_element` is focus plus ENTER.
4. **Typing.** A real `<input>` gets `send_keys`; an app-drawn field is typed key by key on the on-screen keyboard by `_type` (`appium_tv.py:374`). The field is checked before and after: a mismatch, or any error after the first key, raises `E0405`, so no fallback types the text again.
5. **Screenshots.** Tizen sets `native_screenshot=False` (an Appium screenshot hangs the session), so projects use `camera_screenshot`.

TV chromedrivers are old (Tizen 5.5: Chrome 69; webOS 4: Chrome 53): JS must be ES5, script arguments use the legacy `ELEMENT` key, and nothing calls the element rect endpoint. A remote press costs about a second.

## Element location pipeline (deep dive)

- **`StrategyManager`** (`strategies.py:611`) — one per `ActionKeyword` and `Verifier`. It owns `locator_strategies` (`StrategyFactory`, `:558`), `screenshot_strategies` (`ScreenshotFactory`, `:588`; rejects black screens) and `pagesource_strategies` (`PagesourceFactory`, `:580`), built per instance of the element-source `InstanceFallback`, so several sources multiply the list.
- **`StrategyFactory.create_strategies`** (`:507`) filters by `supports` and sorts by priority: XPath(1) < TextElement(2) < TextDetection(3) < ImageDetection(4).
- **`StrategyManager.assert_presence(elements, element_type, timeout, rule)`** (`:707`) backs `Verifier.assert_presence` (`api/verifier.py:200`). `_assert` (`:801`) owns the deadline and polls in rounds (`_assert_round`, `:859`), giving each strategy one non-waiting `check_elements` call on pending elements until the rule (`any`/`all`) is met. Vision strategies share one screenshot per round, run less often while a cheaper strategy still looks, and skip an unchanged screen; a strategy that raises is dropped. `ElementSourceInterface.check_elements` (`common/elementsource_interface.py:102`) defaults to the source's `assert_elements` with a 1 s timeout.
- **`LocateValueWithFrame`** (`:22`) is the vision return shape `(value, annotated_frame)`; `annotated_frame` is saved by `_save_annotated_for_result` (`action_keyword.py:67`).
- **AOI** — `TextDetectionStrategy.locate_with_aoi` (`:217`) and `ImageDetectionStrategy.locate_with_aoi` (`:315`) crop to the area of interest and map coordinates back; used only when `aoi_x/y/width/height` differ from `0/0/100/100`.
- **`execution_tracer`** (`common/execution_tracer.py`) is called from `_try_strategy_locate` and the assertion loop (at most once per strategy per assertion). Read it to see which strategy worked.
- **`keyword_outcome` hooks** — `ExecutionTracer.log_attempt` (`execution_tracer.py:11`) calls `keyword_outcome.looked` (`keyword_outcome.py:46`, drops errors logged before the lookup and keeps the first strategy that found the element); `_act_until_success` calls `act_failed` (`keyword_outcome.py:56`, drops a failed act's errors) and `acted` (`keyword_outcome.py:62`, which keeps errors so one logged after a successful act still counts as silent).

### Four fallback layers — keep them straight

| Level | Where | Iterates over | Trigger to advance | When exhausted |
|------|-------|---------------|---------------------|----------------|
| 1 — param | `TestRunner._try_execute_with_fallback` (`test_runnner.py:549`) | Cartesian product of `${name}` value lists from `ElementData` | `OpticsError` with code starting `E02` or `== X0201` | `_handle_fallback_exhausted` (`:617`) |
| 2 — strategy | `StrategyManager.locate` (`strategies.py:758`) generator | XPath → Text → OCR → Image | strategy yields no result | raises `OpticsError(Code.E0201, ...)` (`:785`) |
| 3 — driver / source | `InstanceFallback.instances` (`base_factory.py:210`) | Enabled instances in `config.yaml` order (`act` is pinned to its owning driver via `routed_to`) | call-site `try/except` per instance | call-site raises (varies) |
| 4 — AI self-heal | `ActionKeyword._ai_self_heal` (`action_keyword.py:245`), backed by `AISelfHealHandler` (`common/ai_self_heal.py:244`) | Up to `max_steps` (default 5) LLM-driven keyword calls | the call doesn't complete the goal | `give_up`, an error or the budget — the original `E0201`/`X0201` is raised |

The chains are independent; `Code` tells level 1 which ladder raised.

**Level 4 — AI self-heal (opt-in).** When level 2 exhausts inside `_act_until_success` (`action_keyword.py:471`), it calls `self._ai_self_heal(...)` (`:245`) before raising. It is **inert unless enabled**: `Config.ai_self_heal: bool = False` (`config_handler.py:162`) *and* a working `llm_models` entry (`_ai_self_heal_ready`, `action_keyword.py:283`); a broken LLM degrades to inert. `AISelfHealHandler.heal` (`ai_self_heal.py:340`) runs a bounded ReAct loop over screenshot + `screen_snapshot` ref rows + the failed intent, with `HEAL_ACTION_SCHEMA` (`ai_self_heal.py:134`). Self-heal does not use `AgentSession`; it reuses only `screen_snapshot.ladder` and `agent_core.bind`. A ref target becomes its `ladder` in `_bind_target` (`ai_self_heal.py:429`), so the recorded step keeps a stable locator, and params are logged in the form the CSV runner binds (a param past the hidden AOI params replays as `index=<n>`). Keyword actions run through `ActionKeyword._heal_execute` (`action_keyword.py:343`) on the allowlist in `_heal_dispatch` (`:233`) — `press_element`, `enter_text`, `scroll`, `swipe_by_percentage`, `press_keycode`, `press_by_percentage` — so healing uses the same locate ladder, with self-heal disabled during each call to avoid recursion. A recovered step joins `_recent_steps` (`:231`) for `/save`. Self-heal curates its steps through the same `curate_steps` as NL mode (`step_curation.py`), so the two loops are siblings that must be kept in sync.

## Keyword entry points (there are eight)

Adding a method to an API class is **not enough** if the keyword should be reachable everywhere.

1. **CSV/YAML runner** — `RunnerFactory.create_runner` (`execution.py:240`) calls `register(instance)` (`keyword_register.py:22`) on each API class, so new public methods are picked up automatically. Caller text `Title Case Words` is normalised via `func_name = "_".join(name.split()).lower()` (`test_runnner.py:454`).
2. **Python SDK / Robot Framework** — `optics.py:Optics` (`:147`) is a `@library(scope="GLOBAL")` class with an explicit `@keyword("Pretty Name")` method per keyword (e.g. `press_element` at `optics.py:683`) delegating to the API instances; `keyword` (`optics.py:55`) / `library` (`optics.py:66`) are no-op fallbacks without `robotframework`. **No auto-registration.** `@fallback_params` (`optics.py:99`) gives param-level fallback for `Union[str, List[str]]` params at the SDK boundary.
3. **HTTP server (`optics serve`)** — `helper/serve.py` mounts `common/expose_api.py`. `discover_keywords()` (`expose_api.py:439`) reflects over `optics_framework.api.*` (`_extract_keywords_from_class` (`:410`) skips `_*` and `test*` methods; `_humanize_keyword` (`:223`)). Types and docstrings flow into OpenAPI, so keep them accurate. The server is **unauthenticated**.
4. **Code generation (`optics generate`)** — `helper/generate.py` emits pytest or Robot code. Update `TestFrameworkGenerator.keyword_registry` (`generate.py:242`) or the keyword is silently skipped; `PytestGenerator` (`generate.py:322`) and `RobotGenerator` (`generate.py:440`) render; `YAMLDataReader._parse_step` (`generate.py:153`) uses the `keyword_registry` set in `read_modules` (`generate.py:172`) to split multi-word names.
5. **`optics list`** — `list_api_methods` (`helper/list_keyword.py:7`) reflects the API classes; `Optics`-only keywords don't show.
6. **Robot `Library    optics_framework.optics.Optics`** — only `@keyword` methods on `Optics` (same source as 2).
7. **`optics live`** — `LiveController._build_registry` (`helper/live.py:433`) uses the runner's auto-registration, so new API methods work in the REPL/TUI and NL mode with no extra wiring.
8. **MCP server (`optics mcp`)** — the `core` toolset reaches every agent-visible keyword through `run_keyword` (`agent_core.keyword_catalog`); `--toolset full` registers each public API method as a string-typed tool. Both dispatch through `expose_api.execute_keyword`. A dedicated core verb needs a case in `agent_core.prepare` and a tool in `build_server`.

- Add `def <name>(...)` on `ActionKeyword` (`api/action_keyword.py:191`).

- Run `optics list` to confirm reflection picks it up.

## Key data structures

- **Execution graph** — `TestCaseNode` (`models.py:77`) → `ModuleNode` (`:43`) → `KeywordNode` (`:37`), each with `state: State` (`:9`) mirroring `EventStatus` (`events.py:13`). Traverse with `current = head; while current: ...; current = current.next`.
- **`ElementData.elements: Dict[str, List[str]]`** (`models.py:154`) — name → ordered fallback list. `get_element(name)` returns the list (execute), `get_first(name)` the first value (dry-run / `resolve_param`).
- **`OpticsError` codes** (`error.py:35`; severities `E` / `W` / `X`):
  - `E0105` keyword not supported on this device platform → fatal, **not** in the `E02*` family.
  - `E0106` driver session gone. Raised by `raise_if_session_dead` (`common/session_liveness.py`) from broad `except` blocks in `strategies.py` that would otherwise report `E0201`/`E0202`/`E0303`/`E0403`; each driver defines what counts via `DriverInterface.is_dead_session_error`, and Appium/Selenium also count a refused connection on a `/session/` URL (`is_webdriver_server_unreachable` (`common/session_liveness.py:15`), so a remote OCR/image service that is down stays a strategy miss). Also raised when `Appium.web_context` can't switch back to `NATIVE_APP`. Reported as `ERROR`, not `FAIL`. Fatal, **not** in the `E02*` family.
  - `E0201` element not found in one source → drives fallback **levels 1 and 2**; `X0201` not found after all fallbacks → also keeps the ladder going.
  - `E0205` invalid element type. `E0303` screenshot empty/black (`ScreenshotStrategy.capture`, `strategies.py:541`). `E0402` keyword not in `keyword_map`.
  - `E0405` the action ran but the screen doesn't show its result → re-raised at once, so no other strategy, self-heal or fallback acts again.
  - `E0501` config / required files missing. `E0701` execution failed. `E0702` test case / session missing. `E0706` the run stopped (Ctrl-C/SIGTERM) before the test case finished; `JUnitEventHandler._end_with_error` puts it on the `<error>` and the running `<kw>`. `E0801` uncategorised error.
- **`Event`** (`events.py:33`) — `entity_type ∈ {"execution","test_case","module","keyword","session"}`, ids, `status`, `args`, timings, `logs` (via `LogCaptureBuffer`, `Junit_eventhandler.py:103`).
- **`LocateResult`** (`strategies.py:596`) — `(value, strategy, annotated_frame, is_coordinates)`; `value` is an `(x, y)` tuple (vision) or a backend element handle.

## Engine wiring

`Session.__init__` (`session_manager.py:104`) builds `OpticsBuilder` (`optics_builder.py:31`), whose `add_*` methods (`add_llm` at `optics_builder.py:108`) store configs and whose `get_*` methods instantiate lazily through `common/factories.py` (`get_llm` (`optics_builder.py:187`) → `instantiate_llm` (`:158`)). `GenericFactory.create_instance_dynamic` (`base_factory.py:73`) imports `optics_framework.engines.<package>.<name>` and passes the config dict (drivers also get `event_sdk`, element sources a matched `driver=`). Several enabled entries become an `InstanceFallback` (`base_factory.py:208`) — **fallback level 3**.

## Working agreement

- **Never co-author commits.** No `Co-Authored-By: Claude ...` or other AI attribution in commits or PR bodies.
- **Assume Codex reviews every PR.** No dead code, debug leftovers or "fix later" hacks; explain non-obvious choices in the commit body and keep diffs focused.
- **Split large pushes** into logical commits (e.g. scaffolding → core → tests → docs), each green on its own.
- **After pushing or raising a PR, do a gap analysis** of the implementation and the chat history; show the gaps, risks and follow-ups to the user, open GitHub issues for the ones they approve, and reference them in the PR description.
- **No unnecessary code comments.** Comment only a non-obvious *why*; never restate what the code does.

## Hard rules

1. **Run pre-commit before committing** (`poetry run pre-commit run --files <changed>` or the git hook; never `--no-verify`). It chains ruff, bandit, whitespace/YAML/JSON checks, commitizen and gitleaks.
2. **Trace the blast radius before changing a function** (`grep -rn "<name>" optics_framework/ tests/`):
   - Renaming a public method on `ActionKeyword` / `AppManagement` / `Verifier` / `FlowControl` breaks every CSV/YAML that names it, its `optics.py:Optics` wrapper and both `keyword_registry`s in `helper/generate.py`.
   - A keyword's display name (the `@keyword(...)` string and the `generate.py` keys) is independent of the method name; changing only it still needs all three places plus docs.
   - The `E02*` / `X0201` prefix check in `test_runnner.py:580` is load-bearing; don't reuse the prefix for non-element errors.
   - `Event.entity_type` values drive `JUnitEventHandler._handle_test_case_event` (`Junit_eventhandler.py:233`) / `_handle_module_event` (`:271`) / `_handle_keyword_event` (`:281`).
   - Changing how `determine_element_type` (`utils.py:290`) classifies a string changes which strategy fires.
3. **Conventional Commits** — the commitizen hook (`.cz.toml`) rejects anything but `feat:` / `fix:` / `refactor:` / `docs:` / `chore:` / `test:` / `perf:` / `style:` / `build:` / `ci:`.
4. **Python 3.12+ only** (`python = ">=3.12,<4.0"`); use modern typing.
5. **Do not edit generated trees** (`__pycache__/`, `dist/`, `docs/build/`, `.tox/`, `htmlcov/`, `execution_output/`).

## Pitfalls

- **Four `${name}` resolution sites.** `TestRunner.resolve_param` (`test_runnner.py:294`) returns the *first* value and `_build_param_candidates` (`:513`) the *list* — dry-run vs execute divergence usually traces here. `FlowControl._resolve_param` (`api/flow_control.py:77`) and `Verifier._resolve_param` (`api/verifier.py:178`) use `utils.resolve_scalar_param` (`common/utils.py:62`), which resolves only a param that is exactly one `${name}` and raises `E0201` for a missing variable. `utils.substitute_inline` (`common/utils.py:104`) replaces `${name}` inside a longer param with the first value (`E0403` if unknown; a whole-param `${name}` is left to the runner forms; `$${name}` escapes); keywords marked `@substitutes_own_vars` (`Condition`, `Evaluate`, `Read Data`) are skipped.
- **Four fallback layers.** "Element not found after retries" usually means level 2 exhausts before level 1 retries — check `execution_tracer` logs. With `ai_self_heal` on, a level-4 recovery can mask a terminal `E0201`/`X0201`; look for the "AI self-heal" log lines.
- **`KeywordRegistry.register` is greedy.** Every public callable becomes a keyword and may collide across API classes (only a warning at `keyword_register.py:37`). Prefix helpers with `_`.
- **`act` must handle both locate shapes** (`(x, y)` tuple or element handle). Any exception in `act` counts as that strategy failing, so a bug in `act` looks like element-not-found.
- **`optics.py:Optics` ≠ the runner's keyword set.** The runner, HTTP API and `optics list` reflect the API classes; the SDK uses explicit `Optics` methods. They can drift.
- **Async re-entrancy.** `ExecutionEngine.execute` must run inside `asyncio.run(...)` via `BaseRunner.run`. `PytestRunner` (`test_runnner.py:1137`) uses `queue_event_sync` (`:111`), which runs each subscriber in its own `asyncio.run`, on a worker thread when `pytest.main` runs inside the batch's loop; don't mix the two paths.
- **`Session` mutates the passed-in `Config`** (`json_path`, `execution_output_path`); don't share a `Config` across sessions.
- **Truncated JUnit XML on long runs** → raise `OPTICS_EVENT_DRAIN_TIMEOUT_S` (default `2.0`) before debugging logic.
- **Robot Framework is optional.** Don't hard-import `robot.api`; mirror the try/except in `optics.py`.
- **Stubbed source methods hide strategies.** `LocatorStrategy._is_method_implemented` (`strategies.py:71`) excludes a source whose method only raises `NotImplementedError`, so a badly stubbed source silently drops out.
- **Two test trees.** `tests/units/` and `tests/integration/` run under one `pytest` (`testpaths = ["tests"]`). Markers: `white_box`, `black_box`, `hybrid`, `generate`.
