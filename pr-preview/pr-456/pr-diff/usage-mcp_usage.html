144!!! warning "`terminate_session` raises on an unknown session id"
145 It used to return `{"status": "terminated"}` unconditionally, including for a
146 session id that did not exist or had already been released. It now raises
147 `ToolError("Session not found")`, mirroring the `404` the REST endpoint
148 returns.
149
150 This matters for agents that fire a defensive `terminate_session` during
151 cleanup: a second call after a successful one is now an error, not a no-op.
152 Track whether you have already released the session, or treat
153 `"Session not found"` as success in your cleanup path.
154
155 Teardown itself is unconditional — a driver that fails to quit still releases
156 the session, its temp directory, and its event manager, and the failure is
157 reported rather than swallowed. The call can block for up to 60 seconds while
158 it waits for an in-flight keyword on that session to finish.
