tt1# Parallel sessions & async-correctness audit — optics-framework
2
3Consolidated from five independent audits at `2a233a0`. Deduplicated; each finding has a stable ID for reference in the implementation plan.
4
5**One-line answer to "why doesn't it support multiple sessions in parallel?"**
6Not one reason. Four independent families, any one of which alone would break it:
71. The keyword execution path blocks the event loop (`A1`), so concurrency is cooperative in name only.
82. Five process-global singletons hold what should be per-session state (`D1`–`D5`).
93. Every artifact path is per-*project*, not per-*session*, and two of them are non-atomic read-modify-writes (`E1`–`E3`).
104. Nothing allocates the exclusive external resources parallel sessions need — most starkly, `systemPort`/`wdaLocalPort` are **never set anywhere in the tree** (`F1`).
11
12**The good news, stated up front.** The correct architecture already exists in exactly one place — `optics_framework/common/execution.py:189`:
13```python
14async with session.keyword_lock:
15 result = await asyncio.to_thread(method, *deserialized_params)
16```
17Sync engines, one async seam, per-session lock. The work is not *adding* concurrency; it is making that the only seam and deleting the state that assumes one session. And `Appium.attach_to_session` (`optics_framework/engines/drivers/appium.py:391`) is a working re-attach to an existing remote session — currently unreachable from HTTP, and the single highest-leverage asset for statelessness.

41**Does the `cfda461` fix generalize? No.** It wrapped exactly two things — `KeywordExecutor.execute`'s method call and `session_manager.create_session`. It does not cover `BatchExecutor`/`DryRunExecutor` (A1 — the pattern needed to go one layer deeper, into `TestRunner`), `delete_session` (A2 — the mirror image, left unwrapped), `PytestRunner` (A4), or the per-request registry rebuild (A8, which sits *outside* both the lock and the thread). Note also `TestRunner._try_execute_with_fallback` has **no `keyword_lock` equivalent** — fixing A1 by dropping `to_thread` in *without* a per-session lock would let concurrent test cases race the same driver.

149## K. The statelessness question, honestly
150
151| Layer | Stateless-able? | Notes |
152|---|---|---|
153| HTTP request handling | **Yes — already is** | No request context beyond path params. |
154| Keyword registry / API instances | **Yes — it's derived, not state** | Pure function of config. Cache per session (also fixes A8). |
155| Execution state (`ElementData`, `ModuleData`, `test_cases`, `apis`, templates, recording buffer) | **Yes** | All JSON-serializable. |
156| Artifacts | **Yes — already is for serve** | `save_captures=False` + base64 responses. Modulo E8, which violates it in practice. |
157| Session registry | **Directory yes, object no** | Can externalize `{id → host, caps, remote driver id, TTL}`. Cannot serialize a live `webdriver.Remote`. |
158| Event / SSE stream | **No, not without replacing the transport** | `session.event_queue` is an in-process `asyncio.Queue`; an SSE subscriber must land on the owning process. **This is the sleeper cost of multi-process** — a bigger change than replacing the registry, and easy to under-scope. |
159| Driver connection | **Appium: effectively yes. Selenium: ~40-line port. Playwright: no.** | Appium re-attaches from `(url, session_id, caps)`. Selenium's `get_driver_session_id` raises `NotImplementedError` and there's no `attach_to_session` — same `newSession`-interception trick, feasible. **Playwright launches its own in-process browser subprocess driven over a pipe by a global loop thread; `get_driver_session_id` returns the constant `"PLAYWRIGHT_SESSION"`; there is no `connect_over_cdp` anywhere. Hard-pinned to the process for its whole life.** |
160
161**Honest definition to adopt:** "stateless `optics serve`" = (a) no server-local *authoritative* state; (b) any instance can serve any request given the externalized handle; (c) a process restart loses no session. Achievable for Appium + inline artifacts + externalized registry + externalized event bus. **Not achievable for in-process Playwright, nor for locally-attached USB devices — there, host affinity is physical, not architectural, and no amount of Redis fixes it.**
162
163Also note: `asyncio.Lock` is process-local. `session.keyword_lock` is the *only* thing preventing interleaved WebDriver commands, and a WebDriver session is not concurrency-safe — so distributed serialization requires a distributed lease, not just a shared registry.
