1072When you run `optics execute` or `optics dry_run`, the framework reads the target folder's own `config.yaml`. Any field you leave out falls back to the built-in defaults (for example, every source defaults to `enabled: false`). tt1074### Environment variables and relative paths
1075
1076Any string value in `config.yaml` can refer to an environment variable or to a file in the project. Use this for values that must not go into the file, such as an Appium hub URL that contains a token, and to keep a project that you copy or unzip somewhere else runnable:
1077
1078```yaml
1079driver_sources:
1080 - appium:
1081 enabled: true
1082 url: $APPIUM_URL
1083 capabilities:
1084 udid: ${DEVICE_UDID:-emulator-5554}
1085 app: ./apps/app.apk
1086event_attributes_json: ./creds/event_attributes.json
1087```
1088
1089```bash
1090export APPIUM_URL="https://hub.example.com/wd/hub?token=..."
1091optics execute my_project
1092```
1093
1094- `$NAME` and `${NAME}` are replaced with the value of `NAME`. If `NAME` is not set or is empty, the run stops and tells you which variable it needs.
1095- `${NAME:-default}` uses `default` when `NAME` is not set or is empty.
1096- A reference can be part of a longer string, for example `https://${HUB_HOST}/wd/hub`. Write `$$` for a literal `$`.
1097- A value that starts with `./` or `../` is a path from the project folder (the folder you give to `optics execute`), not from the folder you run the command in. If the file is not there, the run stops and shows the full path it looked for. Output paths (`execution_output_path`, `log_path`, `json_path`, `project_path`) are resolved the same way but need not exist yet.
1098- An environment variable can hold a relative path: `$CREDS_FILE` set to `./creds/key.json` is resolved like the literal value.
1099- The result is always a string. Optics fields such as `enabled: ${USE_APPIUM}` accept `true` and `false`, but a capability that needs a number gets the number as text.
1100
1101`optics execute`, `optics dry_run`, `optics live` and `optics doctor` resolve these values when they read the file. The Playwright driver's `url` and `capabilities.headers` are the exception: the driver expands them, with the same rules, when it connects, so it can mask the values in its error messages. `optics configure --edit` keeps them as written when it saves the file. The Python SDK and the `optics serve` and `optics mcp` session APIs take the config as data, not as a file, and do not expand references.
