n5## :material-rocket: Quick Startn5!!! abstract "A few terms first"
6 - **Engine** — an installable backend that does the work: an action *driver* (Appium, Selenium, Playwright), an OCR engine, or an LLM. Install engines with `optics setup`.
7 - **Element source** — where Optics looks for on-screen elements (the driver's page source, OCR text, or image matching), configured under `elements_sources` in `config.yaml`.
8 - **Locator** — the value that identifies one element: an XPath, a `text=…` string, a CSS selector, or an image filename.
9 - **Element** — a named locator you reference from a module as `${name}`, defined in `elements.csv`.
10
11!!! tip "In a hurry?"
12 Run **`optics quickstart`** — the [guided walkthrough](#optics-quickstart-the-guided-walkthrough) below documents every stage, defaults included. The rest of the page explains each piece and how to do it by hand.

14## `optics quickstart`: The Guided Walkthrough
15
16One command takes you from nothing to a runnable project:
17
18```bash
19optics quickstart
20```
21
22It walks through eight stages, in order:
23
241. Prints the welcome banner and the golden path.
252. Asks what you want to automate: `mobile` or `web`.
263. Offers to pip-install the matching engines (Appium for mobile, Selenium + Playwright for web).
274. Offers starting points: an empty project (recommended) or a packaged sample (`contact`, `youtube`, …). Picking a sample aimed at the other domain asks for confirmation first.
285. Names the project folder and picks where it lives.
296. Runs a short config Q&A scoped to your platform choice, then writes a commented, platform-correct `config.yaml`.
307. Verifies the environment and the fresh project with `optics doctor`.
318. Prints next steps tailored to your answers.
32
33Every question ships with a default, so pressing Enter throughout yields a runnable project:
34
35| Stage | What it asks | Default (just press Enter) |
36|---|---|---|
37| Target | `mobile` or `web`? | `mobile` |
38| Engines | Install them now? | yes |
39| Starting point | Empty project or a sample? | empty project (recommended) |
40| Project name | Folder name for the new project | `my-optics-project` |
41| Location | Where to create it | current directory |
42| Platform | Android / iOS, or Playwright / Selenium | Android (mobile), Playwright (web) |
43| Details | Device name, app id, server URL, browser, headless | Working examples: `emulator-5554`, `com.example.app`, `http://127.0.0.1:4723`, Chromium, headed |
44| Vision | Find elements by on-screen text (EasyOCR)? | no |
45| Log level | `DEBUG` to `ERROR` | `INFO` |
46
47The defaults are runnable placeholders, not magic: edit the generated `config.yaml` whenever you like, or redo the Q&A with `optics configure <folder>`. Samples ship their own curated `config.yaml`, and the wizard keeps it unless you explicitly agree to overwrite.
48
49!!! info "Prerequisites, the short version"
50 A standard Python 3.12+ virtualenv is all you need to start. Web targets need nothing more (the Playwright engine downloads its own browsers); mobile additionally needs a JDK (17+), Node.js + the Appium server, and the Android platform-tools — the full list lives in [Installation](prerequisites.md). You don't need to settle this up front: the `doctor` check in stage 7 reports each gap with the exact command that fixes it.
51
52The rest of this page explains **what each stage sets up**, so you can also drive every part yourself if you prefer full control.

155!!! tip "Newlines and special characters in CSV"208!!! tip "Newlines and special characters in CSV"
156 XPaths and other locator strings in CSV stay one line per row. To include a newline in a value (e.g. in `@content-desc`), use `\n`; for a tab use `\t`, and for a literal backslash use `\\`.
