566When no element source lists elements, as with a camera, the screen rows come from OCR: each row is a
567text the `text_detection` engine reads, as `e7 Text "Settings" [tap]`. OCR cannot tell a button from a
568label, so every row offers `tap`, and you type with `run_keyword enter_text_using_keyboard` after you tap
569the field. A row keeps its ref while its letters and digits stay the same, so a moving camera frame does
570not give new refs, and a read that differs only by case or punctuation keeps the row's text. OCR can
571still split or misread a line between frames; that line then gets a new ref. When two rows hold the same text, a tap on the second one presses that text with `index=1`, and the steps record it so; other actions refuse such a row. The index follows the order in which `easyocr` and `pytesseract` read the screen. A tap on a row is found by OCR, so `verified` stays `unknown`; read the `check` lines.
