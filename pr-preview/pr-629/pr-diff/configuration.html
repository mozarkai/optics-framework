359 ### `nl_agent`
360
361 **Type:** `object` | **Default:** `{vision: auto, max_steps: 15, escalation_model: ""}`
362
363 Settings of the natural-language mode of `optics live` (`Ctrl-N`). They have an effect
364 only when an entry under `llm_models` is enabled.
365
366 | Key | Meaning |
367 |-----|---------|
368 | `vision` | When the agent sends the screenshot. `auto` sends it on the first turn, after a step that code did not confirm, when the screen has few or unlabelled controls, and when no element list is available. `always` sends it on every turn. `never` sends no image, for text-only models. |
369 | `max_steps` | The most actions the agent takes for one instruction. |
370 | `escalation_model` | A model ID for the same engine as the first enabled `llm_models` entry. The agent sends hard turns to it: a second try after a bad reply, a turn after two failures in a row, and a turn with a guard note. Empty means one model for all turns. |

nn427 !!! info "Idle wait before each command"
428 Before each command, UiAutomator2 (Android) and XCUITest (iOS) wait for the app to
429 stop changing. Their own limit is 10 seconds, so on a screen that never stops
430 changing (a running timer, a focused input) every step takes 10 seconds or more.
431 Optics sets the limit to 1 second. Your `appium:settings` merge with this default.
432 To change the limit, set `waitForIdleTimeout`: Android takes milliseconds, iOS
433 takes seconds, and `0` disables the wait on both:
434
435 ```yaml
436 capabilities:
437 appium:settings:
438 waitForIdleTimeout: 0
439 ```

497 **Remote browser:** set `url` to a remote browser's endpoint and Optics connects to that browser instead of launching one. It works with any browser grid or service that speaks one of Playwright's two remote protocols:
498
499 | `protocol` | Playwright call | Speaks to |
500 |------------|-----------------|-----------|
501 | `cdp` (default) | `connect_over_cdp` | Any Chrome DevTools Protocol endpoint (`ws://`, `wss://`, or `http://` for `/json/version` discovery). Chromium-based browsers only (`browser: chromium`) |
502 | `playwright` | `connect` | A Playwright server (`playwright run-server`, or a grid built on one). Any `browser`; the server's Playwright version must match the client's |
503
504 Use the protocol the provider documents for Playwright's `connect_over_cdp` or `connect`; a `/playwright` path in a url does not by itself mean the Playwright protocol. A mismatch shows up as a connect timeout. Whatever a provider needs, such as browser version, OS or session options, goes in the url's query string as that provider documents it, often as URL-encoded JSON. Credentials go in `headers` or in the url, written as `${NAME}` references:
505
506 ```yaml
507 driver_sources:
508 - playwright:
509 enabled: true
510 url: "wss://grid.example.com/session?options=%7B%22browserVersion%22%3A%22latest%22%7D"
511 capabilities:
512 protocol: cdp
513 headers:
514 Authorization: Bearer ${GRID_TOKEN}
515 connect_timeout_ms: 90000
516 ```
517
518 The same keys cover the common shapes. Check each provider's docs for its current endpoint and options:
519
520 | Remote browser | `url` | `protocol` | Credentials |
521 |----------------|-------|------------|-------------|
522 | Chrome started with `--remote-debugging-port=9222 --user-data-dir=<dir>` | `http://127.0.0.1:9222` | `cdp` | none, or the profile's own sign-ins with `context: existing` |
523 | A CDP grid that takes a token in the query, such as Browserless | `wss://<host>?token=${GRID_TOKEN}` | `cdp` | in the url |
524 | A CDP grid that takes headers | `wss://<host>/<path>` | `cdp` | `headers` |
525 | A Playwright server or grid, such as `npx playwright run-server` | `ws://<host>:<port>/` | `playwright` | `headers`, if any |
526 | A Playwright grid with capabilities in the query, such as BrowserStack (`caps=`) or LambdaTest (`capabilities=`) | `wss://<host>/playwright?caps=<URL-encoded JSON with ${USER} and ${ACCESS_KEY}>` | `playwright` | inside the capabilities JSON |

528 `${NAME}` in `url` or in a header value is replaced with that environment variable when the browser starts, so credentials stay out of the suite. The value is substituted as is, so inside a URL-encoded query write the reference itself unencoded. An unset or empty variable fails the launch with an error that names it. Only the url's host is logged, and secret values and the url's path and query are masked in connect errors. `Close And Terminate App`, or the end of the run, closes the connection, which is what ends the session on the provider's side. No local browser download (`playwright install`) is needed.
529
530 By default Optics opens a fresh context, with the configured `viewport`, in the remote browser. Set `context: existing` to use the browser's own context and its open tab instead, when a provider documents `browser.contexts[0]` because its session settings or recording live there, when a browser cannot create new contexts, or to reuse a signed-in profile. The page then keeps the browser's own window size, `viewport` is not applied, and ending the run disconnects without closing that context's tabs.
531
532 `${NAME}` references are read only from a project's `config.yaml`. `optics serve` and `optics mcp` reject them in a session request, so a caller cannot make the server send one of its environment variables to an endpoint the caller picked. A caller sends the values themselves in `url` and `capabilities.headers`.
