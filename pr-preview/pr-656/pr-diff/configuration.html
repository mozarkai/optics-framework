468 **Remote browser:** set `url` to a remote browser's endpoint and Optics connects to that browser instead of launching one. It works with any browser grid or service that speaks one of Playwright's two remote protocols:
469
470 | `protocol` | Playwright call | Speaks to |
471 |------------|-----------------|-----------|
472 | `cdp` (default) | `connect_over_cdp` | Any Chrome DevTools Protocol endpoint (`ws://`, `wss://`, or `http://` for `/json/version` discovery). Chromium-based browsers only (`browser: chromium`) |
473 | `playwright` | `connect` | A Playwright server (`playwright run-server`, or a grid built on one). Any `browser`; the server's Playwright version must match the client's |
474
475 Use the protocol the provider documents for Playwright's `connect_over_cdp` or `connect`; a `/playwright` path in a url does not by itself mean the Playwright protocol. A mismatch shows up as a connect timeout. Whatever a provider needs, such as browser version, OS or session options, goes in the url's query string as that provider documents it, often as URL-encoded JSON. Credentials go in `headers` or in the url, written as `${NAME}` references:
476
477 ```yaml
478 driver_sources:
479 - playwright:
480 enabled: true
481 url: "wss://grid.example.com/session?options=%7B%22browserVersion%22%3A%22latest%22%7D"
482 capabilities:
483 protocol: cdp
484 headers:
485 Authorization: Bearer ${GRID_TOKEN}
486 connect_timeout_ms: 90000
487 ```
488
489 The same keys cover the common shapes. Check each provider's docs for its current endpoint and options:
490
491 | Remote browser | `url` | `protocol` | Credentials |
492 |----------------|-------|------------|-------------|
493 | Chrome started with `--remote-debugging-port=9222 --user-data-dir=<dir>` | `http://127.0.0.1:9222` | `cdp` | none, or the profile's own sign-ins with `context: existing` |
494 | A CDP grid that takes a token in the query, such as Browserless | `wss://<host>?token=${GRID_TOKEN}` | `cdp` | in the url |
495 | A CDP grid that takes headers | `wss://<host>/<path>` | `cdp` | `headers` |
496 | A Playwright server or grid, such as `npx playwright run-server` | `ws://<host>:<port>/` | `playwright` | `headers`, if any |
497 | A Playwright grid with capabilities in the query, such as BrowserStack (`caps=`) or LambdaTest (`capabilities=`) | `wss://<host>/playwright?caps=<URL-encoded JSON with ${USER} and ${ACCESS_KEY}>` | `playwright` | inside the capabilities JSON |
498
499 `${NAME}` in `url` or in a header value is replaced with that environment variable when the browser starts, so credentials stay out of the suite. The value is substituted as is, so inside a URL-encoded query write the reference itself unencoded. An unset or empty variable fails the launch with an error that names it. Only the url's host is logged, and secret values and the url's path and query are masked in connect errors. `Close And Terminate App`, or the end of the run, closes the connection, which is what ends the session on the provider's side. No local browser download (`playwright install`) is needed.
500
501 By default Optics opens a fresh context, with the configured `viewport`, in the remote browser. Set `context: existing` to use the browser's own context and its open tab instead, when a provider documents `browser.contexts[0]` because its session settings or recording live there, when a browser cannot create new contexts, or to reuse a signed-in profile. The page then keeps the browser's own window size, `viewport` is not applied, and ending the run disconnects without closing that context's tabs.
502
503 To be signed in and still emulate a `device` or `viewport`, save the sign-ins to a file once and set `storage_state` to it. Every run then opens a fresh context with them, locally or in a remote browser. Sign in by hand in a browser that saves its state when you close it:
504
505 ```bash
506 python -m playwright open --save-storage=auth.json https://example.com
507 ```
508
509 or save the state of a Chrome profile you are already signed in with, started with `--remote-debugging-port=9222 --user-data-dir=<dir>`:
510
511 ```python
512 from playwright.sync_api import sync_playwright
513
514 with sync_playwright() as p:
515 p.chromium.connect_over_cdp("http://127.0.0.1:9222").contexts[0].storage_state(path="auth.json")
516 ```
517
518 The file holds live session cookies, so keep it out of version control. Cookies that belong to a browser extension are left out, because Chromium refuses to set them in a new context. Some sites end a session when the user agent changes, so a `device` can sign you out of them. Through `optics serve` or `optics mcp`, send the state's JSON object as `storage_state` instead of a path.
519
520 To run every session on a remote browser without editing a suite, for example in CI or for an `optics mcp` server, set `OPTICS_PLAYWRIGHT_REMOTE` to a JSON object with `url` and, optionally, `headers`, `protocol` and `context`. It takes precedence over the driver config; timeouts still come from `capabilities`:
521
522 ```bash
523 export OPTICS_PLAYWRIGHT_REMOTE='{"url": "wss://grid.example.com/session", "headers": {"Authorization": "Bearer ${GRID_TOKEN}"}}'
524 ```
525
526 `${NAME}` references are read only from a project's `config.yaml` and from `OPTICS_PLAYWRIGHT_REMOTE`. `optics serve` and `optics mcp` reject them in a session request, so a caller cannot make the server send one of its environment variables to an endpoint the caller picked. A caller sends the values themselves, or the server's operator sets `OPTICS_PLAYWRIGHT_REMOTE`.
