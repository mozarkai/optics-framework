159### Record → save → replay (the reusable-artifact loop)
160
161Individual keyword calls are one-offs. To turn a session into a suite:
162
1631. **`start_recording(session_id)`** — from here, every *successful* action
164 keyword is captured (with its resolved args); observers like `screenshot` and
165 `get_interactive_elements` are not. Mis-fired taps that error aren't recorded.
1662. **Cherry-pick** — `list_recorded_steps`, then `remove_step` / `edit_step` to
167 drop or fix a step, or `clear_recording` to start over.
1683. **`save_test_case(session_id, name, variables?)`** — persists the recording as
169 a replayable test case in the MCP **workspace** (a real optics CSV project;
170 defaults to `~/.optics/mcp_workspace`, override with `OPTICS_MCP_WORKSPACE`).
171 `variables` (a JSON object `{ "hour": "22" }`) parameterizes the module: any arg
172 equal to a default becomes `${hour}`, so the same test case replays with new
173 values. You can also pass explicit `steps` instead of using the recording.
1744. **Replay** — `run_test_case(session_id, name, params?)` replays against the
175 live session and returns per-step pass/fail plus a base64 screenshot on the
176 failing step; `params` overrides `${var}` values. Group test cases with
177 `save_suite` and replay them together with `run_suite`.
1785. **Graduate** — `export_optics_project(dest_path, session_id?)` writes a
179 standalone `optics execute`-able project (CSVs + `config.yaml`);
180 `import_optics_project(path)` reads an existing project back in for editing/replay.
