467 **Remote browser:** set `url` to a remote browser's endpoint and Optics connects to that browser instead of launching one. It works with any browser grid or service that speaks one of Playwright's two remote protocols:
468
469 | `protocol` | Playwright call | Speaks to |
470 |------------|-----------------|-----------|
471 | `cdp` (default) | `connect_over_cdp` | Any Chrome DevTools Protocol endpoint (`ws://`, `wss://`, or `http://` for `/json/version` discovery). Chromium-based browsers only (`browser: chromium`) |
472 | `playwright` | `connect` | A Playwright server (`playwright run-server`, or a grid built on one). Any `browser`; the server's Playwright version must match the client's |
473
474 Use the protocol the provider documents for Playwright's `connect_over_cdp` or `connect`; a `/playwright` path in a url does not by itself mean the Playwright protocol. A mismatch shows up as a connect timeout. Whatever a provider needs, such as browser version, OS or session options, goes in the url's query string as that provider documents it, often as URL-encoded JSON. Credentials go in `headers` or in the url, written as `${NAME}` references:
475
476 ```yaml
477 driver_sources:
478 - playwright:
479 enabled: true
480 url: "wss://grid.example.com/session?options=%7B%22browserVersion%22%3A%22latest%22%7D"
481 capabilities:
482 protocol: cdp
483 headers:
484 Authorization: Bearer ${GRID_TOKEN}
485 connect_timeout_ms: 90000
486 ```
487
488 The same keys cover the common shapes. Check each provider's docs for its current endpoint and options:
489
490 | Remote browser | `url` | `protocol` | Credentials |
491 |----------------|-------|------------|-------------|
492 | Chrome started with `--remote-debugging-port=9222 --user-data-dir=<dir>` | `http://127.0.0.1:9222` | `cdp` | none, or the profile's own sign-ins with `context: existing` |
493 | A CDP grid that takes a token in the query, such as Browserless | `wss://<host>?token=${GRID_TOKEN}` | `cdp` | in the url |
494 | A CDP grid that takes headers | `wss://<host>/<path>` | `cdp` | `headers` |
495 | A Playwright server or grid, such as `npx playwright run-server` | `ws://<host>:<port>/` | `playwright` | `headers`, if any |
496 | A Playwright grid with capabilities in the query, such as BrowserStack (`caps=`) or LambdaTest (`capabilities=`) | `wss://<host>/playwright?caps=<URL-encoded JSON with ${USER} and ${ACCESS_KEY}>` | `playwright` | inside the capabilities JSON |
497
498 `${NAME}` in `url` or in a header value is replaced with that environment variable when the browser starts, so credentials stay out of the suite. The value is substituted as is, so inside a URL-encoded query write the reference itself unencoded. An unset or empty variable fails the launch with an error that names it. Only the url's host is logged, and secret values and the url's path and query are masked in connect errors. `Close And Terminate App`, or the end of the run, closes the connection, which is what ends the session on the provider's side. No local browser download (`playwright install`) is needed.
499
500 By default Optics opens a fresh context, with the configured `viewport`, in the remote browser. Set `context: existing` to use the browser's own context and its open tab instead, when a provider documents `browser.contexts[0]` because its session settings or recording live there, when a browser cannot create new contexts, or to reuse a signed-in profile. The page then keeps the browser's own window size, `viewport` is not applied, and ending the run disconnects without closing that context's tabs.
501
502 To run every session on a remote browser without editing a suite, for example in CI or for an `optics mcp` server, set `OPTICS_PLAYWRIGHT_REMOTE` to a JSON object with `url` and, optionally, `headers`, `protocol` and `context`. It takes precedence over the driver config; timeouts still come from `capabilities`:
503
504 ```bash
505 export OPTICS_PLAYWRIGHT_REMOTE='{"url": "wss://grid.example.com/session", "headers": {"Authorization": "Bearer ${GRID_TOKEN}"}}'
506 ```
507
508 `${NAME}` references are read only from a project's `config.yaml` and from `OPTICS_PLAYWRIGHT_REMOTE`. `optics serve` and `optics mcp` reject them in a session request, so a caller cannot make the server send one of its environment variables to an endpoint the caller picked. A caller sends the values themselves, or the server's operator sets `OPTICS_PLAYWRIGHT_REMOTE`.
