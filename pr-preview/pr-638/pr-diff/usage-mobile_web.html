tt1# Mobile Web (browsers and WebViews on Android and iOS)
2
3Optics drives web pages on Android and iOS devices through the same Appium session that
4drives native apps. One test can open an app, follow a link into Chrome or Safari, fill a
5web form, and come back to the app, with no browser driver and no context switching in
6your test steps.
7
8## How it works
9
10The Appium session stays in the native context the whole time. Native locators (visible
11text, resource ids, native XPath) and OCR keep working on web pages, because Chrome and
12Safari put the page's text, links, inputs and buttons into the native UI tree.
13
14Web locators, `css=...` and DOM XPath such as `//button[@type='submit']`, go through the
15`appium_web` element source. For each lookup it:
16
171. finds the web content of the app in front and its front tab: Chrome or a debuggable
18 WebView on Android; Safari, an in-app Safari sheet (`SFSafariViewController`), an
19 inspectable `WKWebView` or another inspectable browser on iOS,
202. finds the element in the page and scrolls it into view, closing the on-screen
21 keyboard if it covers the element,
223. converts the element's position to screen coordinates, and
234. returns to the native context.
24
25The press or text entry that follows is a native action at those coordinates.
26
27## Configuration
28
29Enable `appium_web` next to the other Appium sources. `optics quickstart` and
30`optics configure` enable it for Android and iOS projects.
31
32```yaml
33driver_sources:
34 - appium:
35 enabled: true
36 url: "http://localhost:4723"
37 capabilities:
38 platformName: Android
39 automationName: UiAutomator2
40 deviceName: emulator-5554
41
42elements_sources:
43 - appium_find_element:
44 enabled: true
45 - appium_page_source:
46 enabled: true
47 - appium_web:
48 enabled: true
49 - appium_screenshot:
50 enabled: true
51```
52
53Web lookups use a chromedriver that matches the Chrome version on the device. Let
54Appium download it by starting the server with
55`appium server --allow-insecure uiautomator2:chromedriver_autodownload`, or point
56`appium:chromedriverExecutableDir` at a folder of chromedriver binaries.
57
58### iOS
59
60The same `elements_sources` work with `platformName: iOS` and `automationName: XCUITest`.
61No extra driver is needed; XCUITest reads web pages through Safari's Web Inspector.
62
63- **Real devices:** turn on **Web Inspector** and **Remote Automation** in
64 Settings > Apps > Safari > Advanced. Simulators need no setup.
65- **Apps:** a `WKWebView` is readable when the app sets `isInspectable = true`, which
66 apps built with the iOS 16.4 SDK or later need even in debug builds. Safari and in-app
67 Safari sheets are always readable.
68- **Other browsers:** Chrome, Firefox and other iOS browsers are read the same way when
69 they allow inspection. Firefox's tabs are inspectable out of the box; Chrome needs
70 Settings > Content Settings > Web Inspector.
71
72Native iOS sessions start with `includeSafariInWebviews: true`,
73`additionalWebviewBundleIds: ["*"]`, `webviewConnectRetries: 1` and
74`webviewAtomWaitTimeout: 5000`, so Optics sees every app's web content and a page that
75cannot answer costs seconds, not minutes. Values in your `capabilities` take precedence.
76
77## Opening pages
78
79`Launch App` and `Launch Other App` open a URL in the app that handles it, a browser
80for web addresses:
81
82```csv
83module_name,module_step,param_1
84Open Shop,Launch App,https://shop.example.com/
85Back To The App,Launch App,com.example.shop
86```
87
88To open a web page in Chrome even when another browser is the default, call the deep link
89with Chrome's package:
90
91```csv
92module_name,module_step,param_1
93Open Shop In Chrome,Execute Script,"{""script"": ""mobile: deepLink"", ""args"": {""url"": ""https://shop.example.com/"", ""package"": ""com.android.chrome""}}"
94```
95
96To test only the browser on Android, add `browserName: Chrome` to the capabilities: the
97session starts in Chrome, web addresses open there whatever the default browser is, and
98every keyword works as in an app session.

100## Locators
101
102| Locator | Example | Resolved by |
103|---|---|---|
104| Visible text | `Sign in` | native tree, then OCR |
105| HTML id | `searchInput` | native tree (Chrome reports HTML ids as resource ids) |
106| CSS | `css=input[name='q']`, `#searchInput` | `appium_web` |
107| DOM XPath | `//button[@type='submit']` | native sources first, then `appium_web` (assertions skip the native sources for HTML-only paths) |
108
109An XPath that names an Android or iOS class (`android.widget.Button`,
110`XCUIElementTypeButton`) or a native attribute (`@resource-id`, `@text`, `@bounds` and
111the like) outside quotes is left to the native sources. A web locator that matches a
112hidden element fails with "not displayed"; one that matches nothing fails at once.
113
114`Assert Presence` with a web locator checks the DOM, so an element scrolled off screen or
115hidden passes. `Assert Visibility` passes only for an element displayed in the visible part
116of the page.
117
118## Screen elements
119
120`Get Interactive Elements`, `Get Screen Elements`, the MCP `elements` resource and the
121natural-language mode of `optics live` list the web page next to the app's native
122elements. With `appium_web` enabled, one call returns:
123
124- the native elements (Chrome's toolbar, the app around a WebView);
125- every control, piece of text and image of the web page, with screen bounds. An element
126 outside the visible part of the page carries `offscreen: true`; pressing it by locator
127 scrolls it into view;
128- a `loc` on each web control and text: a `css=` or `xpath=` locator that matches only
129 that element. Put it in your elements file.
130
131A web entry replaces the copy of it that UiAutomator2 or XCUITest shows in the native tree.
132
133`loc` stays the same from run to run. It prefers a test attribute (`data-testid`), an id,
134a name or label, or the element's text; when those are shared, it names the element inside
135its card or row, for example
136`xpath=//article[.//h2[normalize-space()='Red Mug']]//button[normalize-space()='Add to cart']`,
137and last a CSS path. It skips generated ids and classes, and matches "Cart (0)" by its
138leading words, so a changing count does not change it.

140## Moving between apps and the browser
141
142Nothing in a test says which app is in front. Every lookup looks at the screen as it is
143now, so a test follows the user's path from one app to another:
144
145```csv
146module_name,module_step,param_1,param_2
147Read The Policy,Press Element,Google Play refund policy
148Read The Policy,Assert Presence,css=h1,30
149Read The Policy,Get Text,css=h1
150Read The Policy,Go Back
151Read The Policy,Assert Presence,Google Play refund policy,20
152```
153
154- **App to browser.** Tapping a link in an app opens Chrome or a Chrome Custom Tab, the
155 in-app browser most apps use. Web locators then find elements in the page in front.
156 `Go Back` closes the tab and returns to the app.
157- **Browser to app.** A web link that an app handles, such as a Play Store link, opens
158 that app. Its native elements are available as soon as it is in front.
159- **Choosing an app.** When more than one app can open a link, Android asks which one to
160 use. Answer with `Detect And Press` on the app's name, then on `Just once`.
161- **Other browsers.** If a link opens in another browser, such as Samsung Internet, web
162 locators fail with "Cannot read the web page shown by …"; text locators and OCR work
163 there. To keep a test in Chrome, make Chrome the device's default browser.
164- **A Custom Tab right after another.** When an app opens a Custom Tab just after one
165 closed, Chrome ignores the first tap on the new tab. Before typing into a field there,
166 press the field once.
167- **Covered elements.** When a banner, a dialog or a panel lies over the element a web
168 locator matches, Optics does not tap it, because the tap would land on whatever covers
169 it. Dismiss the cover first. `Get Text` still reads a covered element.
170
171On iOS, when several web views are on screen, web locators use the one that holds the
172element. To return from Safari to the app, use `Launch App` with the app's bundle id.
173
174## Chrome's own pop-ups
175
176A fresh Chrome shows native pop-ups over the page: a notification prompt, a sign-in
177offer, or terms to accept. While one is open, nothing on the page can be tapped. Grant the
178notification permission before opening Chrome so the prompt never shows:
179
180```csv
181module_name,module_step,param_1
182Prepare Chrome,Launch App
183Prepare Chrome,Execute Script,"{""script"": ""mobile: changePermissions"", ""args"": {""permissions"": ""android.permission.POST_NOTIFICATIONS"", ""appPackage"": ""com.android.chrome"", ""action"": ""grant""}}"
184```
185
186Dismiss any other pop-up with `Detect And Press` on its text or button id:
187`Stay signed out` or `signin_fre_dismiss_button` (sign-in offer), `No thanks` or
188`negative_button` (notification prompt).
189Give it a timeout of 5 seconds or more, because the prompt appears after the page loads.
190
191## WebViews in apps
192
193An app's WebView is reachable only when the app enables WebView debugging
194(`WebView.setWebContentsDebuggingEnabled(true)`), which debug builds usually do. Without
195it, web locators fail with "No web content found in the foreground app". Native
196locators and OCR still work on the WebView's content.
197
198Android sessions start with `ensureWebviewsHavePages: false` and
199`extractChromeAndroidPackageFromContextName: true`, so a frozen background app with WebView
200debugging on adds at most 2 s to a web lookup. Values in your `capabilities` take precedence.
201
202## Limits
203
204- Web locators search the top-level page only, not the inside of an `iframe`. Use text
205 locators or OCR for content in a frame.
206- When several Chrome tabs show the same address and Optics cannot tell which is on
207 screen, web locators fail with "Cannot tell which browser tab is on screen". Close the
208 extra tabs.
209- A web lookup costs one to two seconds on a remote device. Prefer native locators where
210 they work.
211- iOS sign-in sheets (`ASWebAuthenticationSession`) cannot be inspected. Use text
212 locators and OCR there.
213
214The `mobile_web` sample (`optics init --template mobile_web`) runs a Wikipedia search in
215Chrome with these steps.
