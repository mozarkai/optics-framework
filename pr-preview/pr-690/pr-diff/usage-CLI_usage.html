106### Exit codes
107
108`optics execute` and `optics dry_run` exit with:
109
110| Code | Meaning |
111|------|---------|
112| `0` | Every test case passed. |
113| `1` | A test case failed, or the run could not start: a config or environment variable error, missing test files, an unreachable driver, or a credentials file that is not valid. |
114| `2` | The command line is not valid, for example an unknown flag or no project folder. |
115| `3` | The test selection is not valid: a name in `--include`/`--exclude` (or in `include`/`exclude` in `config.yaml`) matches no test case, or nothing is left to run. Also any other value that is not valid (a `ValueError`). |
116| `130` | Stopped with Ctrl-C (SIGINT). |
117| `143` | Stopped with SIGTERM. |
118
119When the run cannot start, stderr shows a *Cannot start* panel titled with the error code, for example `Cannot start: E0501`. Other errors print `Code.<code>: <message>`. See [Error Handling](../architecture/error_handling.md) for the codes.

121### Results
122
123A run writes its results to `execution_output/` in the project folder, or to `execution_output_path` when the config sets it:
124
125- `junit_output.xml`: the JUnit report, written once when the run ends, also when it is stopped with Ctrl-C or SIGTERM. A run has one `<testsuite>` with one `<testcase>` per test case it ran, including suite setup and teardown. Each per-test setup and teardown is a test case of its own, named after the test it wraps, such as `Setup (Login Test)`. The suite `name` and every `classname` are the project folder's name, so unpack a project into a folder named after the suite. The suite `id` is the session id.
126- `junit_output_<session_id>.xml` instead, only when two sessions in one process share the output folder (the Python SDK or `optics serve`). `optics execute` and `optics dry_run` always write `junit_output.xml`.
127- Screenshots, `failed_steps_elements.json`, `interactable_elements.json`, and `logs.json` when `json_log: true`.
128
129| Outcome | Exit | `junit_output.xml` | Sample |
130|---------|------|--------------------|--------|
131| All test cases passed | `0` | Every `<testcase>` has `status="PASS"`. | [passed.xml](junit_samples/passed.xml) |
132| A test case failed | `1` | That `<testcase>` has `status="FAIL"` and a `<failure>` with the reason. | [failed.xml](junit_samples/failed.xml) |
133| A per-test setup failed | `1` | `Setup (<test>)` has a `<failure>`. The test still runs and has its own result. | [setup_failed.xml](junit_samples/setup_failed.xml) |
134| Config or environment variable error | `1` | Not written: the run stops before a session starts. | |
135| Test selection error | `3` | Not written: the run stops before a session starts. | |
136| Error after the session starts, such as a credentials file that is not valid | `1` | `<testsuites/>` with no test cases. | |
137| Stopped with Ctrl-C or SIGTERM | `130` / `143` | Test cases that finished keep their results. The one that was running has `status="ERROR"` and an `<error>`. Later test cases and the suite teardown do not run. | [stopped.xml](junit_samples/stopped.xml) |
