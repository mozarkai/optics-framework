tt301## Popup Events
302
303Popup handling (see [Popup Rules](../usage/popup_rules.md)) publishes a `popup` event for every inspection. It is an
304`Event` of the runner's event manager, like the `test_case`, `module` and `keyword` events, and not an EventSDK
305event, so it reaches the JUnit handler's JSON events and any subscriber.
306
307The event's `entity_id` and `name` are its keyword's, `parent_id` is the module and `message` is the text of the
308popup. `status` is `PASS` for a `handled` or `none` verdict and `FAIL` otherwise, and `code` is the error code
309(`E0206`, `E0207` or `E0208`) when one applies. The rest travels in `args`, because an event's `extra` holds strings
310only:
311
312```json
313{
314 "type": "popup",
315 "session_id": "a41c9e02",
316 "test_case": "Check balance",
317 "module": "Open dashboard",
318 "step_index": 3,
319 "keyword": "press_element",
320 "element": "Balance card",
321 "platform": "android",
322 "app_id": "com.example.bank",
323 "check": "on_failure",
324 "rule": "Rate Us",
325 "priority": 10,
326 "matched": ["text_contains"],
327 "popup_kind": "in_app",
328 "popup_text": "Rate Us Enjoying the app? Maybe Later Rate Now",
329 "action": "tap Maybe Later",
330 "verdict": "handled",
331 "popup_gone": true,
332 "dismissed_in_ms": 730,
333 "step_count": 1,
334 "run_count": 1,
335 "screenshots": ["popup_1_before.png", "popup_1_after.png"],
336 "page_source": null,
337 "code": null,
338 "timestamp": "2026-11-12T10:42:08.150+00:00"
339}
340```
341
342`verdict` is one of `handled`, `limit`, `stopped`, `unknown` and `none` (nothing was on screen), and `popup_kind` is
343`in_app` or `system_alert`. An `unknown` event keeps the first 200 characters of the visible text and the saved page
344source, so a rule can be written from it. A report can group popups by `popup_text`, `rule`, `verdict` and `app_id`.
