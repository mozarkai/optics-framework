370=== "Popups and Permissions"
371
372 ### `popup_rules`
373
374 **Type:** `list` | **Default:** `[]`
375
376 Rules for popups that get in a step's way: what a popup looks like, what to press and what happens next. Off
377 until a rule is defined. The same list can come from `test_data/popup_rules.json` or
378 `Optics.add_popup_rules`; see [Popup Rules](usage/popup_rules.md) for the fields.
379
380 ```yaml
381 popup_rules:
382 - name: Rate Us
383 priority: 10
384 detect:
385 text_contains: ["Rate Us"]
386 action:
387 type: tap
388 target: Maybe Later
389 ```
390
391 ### `permissions`
392
393 **Type:** `object` | **Default:** `{}`
394
395 Permissions to grant (`allow`) or revoke (`deny`) for the app under test right after the session starts, so
396 their prompts never appear. It sits at the top of the config, not in the Appium `capabilities`. On iOS the
397 prompt is answered when it appears, by button label, and every value must be the same: see
398 [Popup Rules](usage/popup_rules.md#permissions-on-ios).
399
400 ```yaml
401 permissions:
402 camera: allow
403 notifications: deny
404 ```
