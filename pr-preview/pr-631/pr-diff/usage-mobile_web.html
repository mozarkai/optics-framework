tt1# Mobile Web (Chrome and WebViews on Android)
2
3Optics drives web pages on a real Android device through the same Appium session that
4drives native apps. One test can open an app, follow a link into Chrome, fill a web form,
5and come back to the app, with no separate browser driver and no context switching in
6your test steps.
7
8## How it works
9
10The Appium session stays in the native context the whole time. Native locators (visible
11text, resource ids, native XPath) and OCR keep working on web pages, because Chrome puts
12the page's text, links, inputs and buttons into the native UI tree.
13
14Web locators, `css=...` and DOM XPath such as `//button[@type='submit']`, go through the
15`appium_web` element source. For each lookup it:
16
171. finds the web content of the app in front (Chrome, or a debuggable WebView) and its
18 front tab,
192. finds the element in the page and scrolls it into view,
203. converts the element's position to screen coordinates, and
214. returns to the native context.
22
23The press or text entry that follows is a native action at those coordinates.
24
25## Configuration
26
27Enable `appium_web` next to the other Appium sources. `optics quickstart` and
28`optics configure` enable it for Android and iOS projects, and the MCP server includes it
29when it fills in the Appium sources for you.
30
31```yaml
32driver_sources:
33 - appium:
34 enabled: true
35 url: "http://localhost:4723"
36 capabilities:
37 platformName: Android
38 automationName: UiAutomator2
39 deviceName: emulator-5554
40
41elements_sources:
42 - appium_find_element:
43 enabled: true
44 - appium_page_source:
45 enabled: true
46 - appium_web:
47 enabled: true
48 - appium_screenshot:
49 enabled: true
50```
51
52Web lookups use a chromedriver that matches the Chrome version on the device. Let
53Appium download it by starting the server with
54`appium server --allow-insecure uiautomator2:chromedriver_autodownload`, or point
55`appium:chromedriverExecutableDir` at a folder of chromedriver binaries.
56
57UiAutomator2 driver 8.6.0 or later converts element positions exactly, including pinch
58zoom. Older drivers work too: Optics computes the position from the page's
59geometry and the on-screen bounds of the WebView.
60
61## Opening pages
62
63`Launch App` and `Launch Other App` open a URL in the app that handles it, a browser
64for web addresses:
65
66```csv
67module_name,module_step,param_1
68Open Shop,Launch App,https://shop.example.com/
69Back To The App,Launch App,com.example.shop
70```
71
72In an app session the URL opens in the device's default handler: the default browser,
73or the app that owns the link. To open a web page in Chrome even when another browser is
74the default, call the deep link with Chrome's package:
75
76```csv
77module_name,module_step,param_1
78Open Shop In Chrome,Execute Script,"{""script"": ""mobile: deepLink"", ""args"": {""url"": ""https://shop.example.com/"", ""package"": ""com.android.chrome""}}"
79```
80
81To test only the browser, start the session in Chrome by adding `browserName: Chrome`
82to the capabilities. Web addresses then open in that Chrome whatever the default browser
83is, and Optics moves the session to the native context as soon as it starts, so every
84keyword works the same way as in an app session.
85
86## Locators
87
88| Locator | Example | Resolved by |
89|---|---|---|
90| Visible text | `Sign in` | native tree, then OCR |
91| HTML id | `searchInput` | native tree (Chrome reports HTML ids as resource ids) |
92| CSS | `css=input[name='q']`, `#searchInput` | `appium_web` |
93| DOM XPath | `//button[@type='submit']` | native sources first, then `appium_web` |
94
95An XPath that names Android or iOS classes or attributes (`android.`,
96`XCUIElementType`, `@resource-id`, `@content-desc`, `@text`, `@package`, `@bounds`) is
97left to the native sources. A web locator that matches an element hidden by the page
98(`display: none`, zero size) fails with "not displayed" instead of tapping blindly.
99
100`Assert Presence` with a web locator checks the DOM, so it passes for any element in the
101page, including one scrolled off screen or hidden. `Assert Visibility` passes only for an
102element that is displayed and inside the visible part of the page.
103
104## Chrome's own pop-ups
105
106A fresh Chrome shows native pop-ups over the page: a notification prompt, a sign-in
107offer, or terms to accept. While one is open, nothing on the page can be tapped. Grant the
108notification permission before opening Chrome so the prompt never shows:
109
110```csv
111module_name,module_step,param_1
112Prepare Chrome,Launch App
113Prepare Chrome,Execute Script,"{""script"": ""mobile: changePermissions"", ""args"": {""permissions"": ""android.permission.POST_NOTIFICATIONS"", ""appPackage"": ""com.android.chrome"", ""action"": ""grant""}}"
114```
115
116Dismiss any other pop-up with `Detect And Press` on its button id:
117`negative_button` (notification prompt) or `signin_fre_dismiss_button` (sign-in offer).
118Give it a timeout of 5 seconds or more, because the prompt appears after the page loads.
119
120## WebViews in apps
121
122An app's WebView is reachable only when the app enables WebView debugging
123(`WebView.setWebContentsDebuggingEnabled(true)`), which debug builds usually do. Without
124it, web locators fail with "No web content found in the foreground app". Native
125locators and OCR still work on the WebView's content.
126
127## Limits
128
129- Web locators work on Android. On iOS, use text locators and OCR: Safari's page content
130 is in the native UI tree there too.
131- Web locators search the top-level page only, not the inside of an `iframe`. Use text
132 locators or OCR for content in a frame.
133- When two Chrome tabs show the same URL, Optics cannot tell which one is on screen and
134 web locators fail with "Cannot tell which browser tab is on screen". Close the extra
135 tab, or open the page once.
136- `Get Text` does not return text for a web locator. Use a text locator, or
137 `Assert Presence`.
138- Each web lookup switches context twice and costs about one to two seconds on a
139 remote device. Prefer native locators where they work, and use `css=` where they do not.
140
141The `mobile_web` sample (`optics init --template mobile_web`) runs a Wikipedia search in
142Chrome with these steps.
