123`e7 button "Sign in" [tap] #login`. `e7` is a ref, the words in quotes are on the screen,

127
128- runs the action through a locator that matches only that element, never through fuzzy text;
129- reads the screen again and judges the step in code: **pass** when the expected text
130 appears (text that was already on the screen proves nothing), **fail** when the action
131 failed or nothing changed and the expectation is not met, and **unknown** otherwise, when
132 the LLM judges it from the screen;
133- accepts **done** only when the goal text that the LLM names is on the screen. A run that
134 ends done without naming any goal text shows as `PASS (unverified)`;
135- asks the LLM once more, with a correction, when a reply cannot run (a ref that is gone, a
136 missing text, a typed value that is not in the instruction or on the screen);
137- stops a run that loops: after 3 failures or 3 gestures in a row, and when actions keep
138 leaving the screen unchanged (it adds a warning note first);
139- sends the screenshot only when it adds information (see `nl_agent.vision` in
140 [Configuration](../configuration.md#nl_agent)).

144`press_element ${sign_in_button}`, and `/save` writes the element to your elements CSV. AI
145self-heal is off while the agent runs, so every step it takes shows in its history.
